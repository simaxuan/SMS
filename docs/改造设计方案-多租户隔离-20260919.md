# 多租户隔离 · 教师账号体系 · 排名 scope 改造设计方案

> 版本：v1.0（2026-09-19）
> 依据：`docs/代码逐行审查报告-20260919.md` 中 M1–M7 / S1 / O1 等架构级问题
> 范围边界：本方案聚焦「读路径 school_id 下推 + SCOPE_SCHOOL 角色模型 + 教师账号落库 + 排名三级 scope」。写入路径必填 schoolId、实体外键/级联、system_setting 按校隔离(S2) 等作为第二阶段另行立项。

## 一、背景与问题（均由逐行审查确认）

| 编号 | 问题 | 现状证据（file:line） |
|---|---|---|
| S1 | 无教师账号创建 API，teacher/seed-admin 的 `schoolId` 恒为 null → 多租户前提失效 | `AuthController.java:30`(register 强制家长)、`AuthService.register:39-42`、`DataSeeder.java:229-236`(admin 未 setSchoolId) |
| M1 | 考试列表全库无 school 过滤 | `ExamService.list:52-53` → `ExamRepository.findAllBySourceOrderByIdAsc` |
| M2 | 学生列表全库无 school 过滤 | `StudentService.list:32-36` → `StudentRepository.search:29-36`(无 school 条件) |
| M3 | 班级/课程/考试类型字典列表全库无过滤 | `DictionaryService.listClasses:45-47`/`listCourses:96-98`/`listExamTypes:127-129`(均 findAll) |
| M6 | 统计/排名/对比/进步对 SCOPE_ALL 跨校失真 | `RankingService.ranking:103-113`、底层 `GradeRepository.rankRows` 无 school 约束 |
| M7 | 缺 SCOPE_SCHOOL 级；SCOPE_ALL=全局无 school 兜底 | `Account.java:24-25`(仅 CLASS/ALL)、`DataScopeService.visibleClassIds:39-43`(ALL→null=全局) |
| O1 | 排名 scope(class/level/school) 参数从未用于过滤 | `RankingService.ranking:98`(仅回写 scope)/`:101-122`(只按 DataScope 收口) |

## 二、改造目标

1. **补齐教师账号体系**：新增「教师管理」入口（创建/列表/删除/停用/重置），创建时强制写入 `schoolId` 与 `scopeType`，使多租户隔离的前提成立。
2. **引入 `SCOPE_SCHOOL` 角色**：表达「仅看本校全部班级」的管理员；`SCOPE_ALL` 收敛为「全校」并**一律叠加当前 `schoolId` 过滤**，不再等于"全库"。
3. **读路径统一 school_id 下推**：学生、考试、班级/课程/考试类型字典、统计/排名/对比/进步，按当前登录 `schoolId` 过滤（`schoolId` 为 null 的全局超管除外）。
4. **排名 scope 三级语义真正生效**：class(按班级分组)、level(按级部聚合)、school(按本校) 各自排名。
5. 不破坏现行演示/seed/admin 流程；向后兼容 `schoolId=null` 的旧数据与种子。

## 三、方案总览

```
角色范围模型:  SCOPE_CLASS(默认)  SCOPE_SCHOOL(新)  SCOPE_ALL(=全校+schoolId兜底)
隔离落点:      Repository 查询统一拼 school_id 条件(经中央 helper 取当前 schoolId)
教师体系:      新 TeacherManagement API + 前端"教师管理"Tab，落 schoolId/scopeType
排名 scope:    后端按 scope 分组(班/级部/校)重算名次
```

## 四、详细设计（每项映射真实代码）

### 4.1 角色/范围模型扩展 —— 【文件：`entity/Account.java`、`service/DataScopeService.java`】

**Account.java**
- `SCOPE_CLASS="CLASS"`、`SCOPE_ALL="ALL"` 保持不变，新增：
  ```java
  public static final String SCOPE_SCHOOL = "SCHOOL"; // 仅看本校全部班级
  ```

**DataScopeService.java（核心：统一取当前 schoolId 的 helper）**
- 新增方法，供全局复用：
  ```java
  /** 中央取当前登录用户的 schoolId（null 表示全局超管，调用方需决定是否放开） */
  public Long currentSchoolId() { return currentUser() == null ? null : currentUser().getSchoolId(); }
  ```
- `visibleClassIds` 扩展：
  ```java
  if (SCOPE_ALL.equals(scopeType)) return null;             // 全校(仍会叠加 schoolId，见 4.3)
  if (SCOPE_SCHOOL.equals(scopeType)) {
      return classRepository.findBySchoolId(user.getSchoolId())  // 本校全部班级
          .stream().map(ClassEntity::getId).collect(toSet());
  }
  // CLASS：教师-班级绑定 集合（现状保持）
  ```
- 说明：`ClassRepository.findByIdSchool` 需要新增 `findBySchoolId(Long)` 派生方法。

### 4.2 读路径 school_id 下推 —— 【文件：`service/ExamService.java`、`service/StudentService.java`、`service/DictionaryService.java`、对应 Repository】

原则：**「有当前 schoolId → 按其过滤；`schoolId==null`(全局超管) → 全量」**，避免破坏 admin/种子。

- **ExamService.list / ExamRepository**：新增 `List<Exam> findBySchoolIdAndSourceOrderByIdAsc(Long, String)`；service：
  ```java
  Long sid = LoginUserContext.requireLogin().getSchoolId();
  return sid == null ? examRepository.findAllBySourceOrderByIdAsc(SCHOOL)
                     : examRepository.findBySchoolIdAndSourceOrderByIdAsc(sid, SCHOOL);
  ```
- **StudentService.list / StudentRepository.search**：search 增加 `@Param("schoolId")` 条件 `(:schoolId is null or s.schoolId = :schoolId)`；service 传当前 schoolId。
- **DictionaryService**：`listClasses`→`classRepository.findBySchoolId(sid)`；`listCourses`→`courseRepository.findBySchoolId(sid)`；`listExamTypes`→`examTypeRepository.findBySchoolId(sid)`（均需新增派生方法；schoolId 为 null 时回退 findAll）。此三处已具备对应实体 `schoolId` 字段。

### 4.3 统计/排名/对比/进步 school 兜底 —— 【文件：`service/RankingService.java`、`service/StatisticsService.java`、`service/ComparisonService.java`、`service/TrendService.java`、`repository/GradeRepository.java`】

- `GradeRepository` 现有 `rankRows/stats/scores/courseRowsByExam` 均 join Student 但没有 school 约束。最低风险做法：在这些查询的统一入口（`RankingService` 组装 `ranked` 后，`StatisticsService`、`ComparisonService`、`TrendService`）**按当前 schoolId 过滤已经 join 出 schoolId 的结果集**（结果行含 student 的 classId，可再 join schoolId；或在 rankRows 的 select 中补出 student.school_id 列），而非改全部 SQL。
- 具体：`RankingService.ranking` 组装 `ranked` 时，若 `user.getSchoolId()!=null`，过滤掉 `schoolId != user.schoolId` 的行。其余统计服务同理。
- 长期（第二阶段）：在 `GradeRepository` 各查询的 JPQL 统一追加 `and s.schoolId = :schoolId`，由中央切面注入。

### 4.4 教师账号体系 —— 【文件：`controller/AuthController.java`、`service/AuthService.java`、`repository/AccountRepository.java`、`dto/CreateTeacherRequest.java`、前端 `views/Organization.vue`】

- **CreateTeacherRequest**（新 DTO）：`username, password, nickname?, phone?, schoolId, scopeType(CLASS/SCHOOL/ALL), classIds[]`。
- **AuthService.createTeacher(req)**：
  - 校验：`username` 唯一、`scopeType∈{CLASS,SCHOOL,ALL}`、`schoolId` 非空（强制归属学校）。
  - `scopeType==CLASS` 时必传 `classIds` 且须为**当前请求者所在学校**的班级（校验 class.schoolId==req.schoolId）。
  - 创建 `Account(role=TEACHER)` 并写 `schoolId/scopeType`；若带 classIds 写 `TeacherClass`。
  - 返回 `toView`。
- **AuthService.listTeachers()**：改为 `findByRoleAndSchoolId(TEACHER, currentSchoolId)`；`schoolId==null` 全局超管仍全量。修 `toView` 隐藏他人手机号：仅本人或同 admin 可见 `phone`。
- **AuthController**：新增 `POST /api/auth/teachers`（创建）、`DELETE /api/auth/teachers/{id}`（停用/删除）、`GET /api/auth/teachers`(已有，改为按校)；仅 `ROLE_TEACHER` + `SCOPE_SCHOOL/ALL` 或 admin 可调用。
- **前端 Organization.vue**：新增「教师管理」Tab，表单含 归属学校/范围/绑定班级(多选，取自该校可选班级)，调用上述 API；老师-班级归属下拉改为按当前 school 过滤。

### 4.5 排名 scope 三级语义 —— 【文件：`service/RankingService.java`】

在 `ranking` 组装 `ranked`（含 classId）后，按 `scope` 分组重排名（已具备 `stat.assignRank(List,ties)`）：
```java
// class：按 classId 分组，各自排名后按班内名次升序展示（同班并列处理不变）
// level：需要 student 的 levelId —— 经 classId → class.levelId 映射分组
// school：当前 schoolId 下全量排名（叠加 4.3 的 school 过滤）
```
- 为支持 level，`GradeRepository.rankRows` 需补出 `classs.level_id`（join Class）或 `RankingService` 用 `classRepository.findById` 映射 classId→levelId（现已有 `support.classNameByIds` 类似能力，可加 `levelIdByIds`）。
- 展示：`row` 增加 `scopeGroup`（班级名/级部名/全校），便于前端表头区分。

### 4.6 种子与旧数据 —— 【文件：`config/DataSeeder.java`】

- 种子 admin 保持 `SCOPE_ALL` 但**补 `setSchoolId(school.getId())`**（使 admin 也归属演示学校，写出数据 school_id 不再为 NULL）。
- 种子 Course/ExamType/Exam/Student 已补 schoolId（本轮已落地）。
- 已有库中 `school_id IS NULL` 的历史行（旧种子/旧创建）保持可读：读路径对 `schoolId` 为 null 时全量放开（4.2 原则），避免误伤。

## 五、风险与兼容性

| 风险 | 缓解 |
|---|---|
| teacher `schoolId` 缺失导致按校过滤空结果 | 创建 API 强制 schoolId；对现有 null 账号读路径放开(4.2) |
| SCOPE_SCHOOL 改动 `visibleClassIds` 影响现有 CLASS 逻辑 | 新增分支不动 CLASS/ALL 既有返回语义 |
| 排名分组改动影响统计口径 | 仅按 scope 分组重排，不改变原始分数/满分；由现有 `StatisticsMetricTest` 回归 |
| 前端教师管理 Tab 牵动组织管理 | 新 Tab 独立，原"老师班级归属"Tab 仅改下拉数据源过滤 |

## 九、阶段 B 目标 · 范围 · 验收标准（2026-09-19 专项）

### 9.1 目标
在阶段 A（读路径字典/学生/考试下推 + 教师体系 + 排名三级 scope）已落地基础上，补齐**统计/对比/进步/排名的 SQL 层 school 兜底**、**system_setting 按校隔离**、**写路径 schoolId 强制**与**数据迁移/删除级联安全网**，使多租户隔离在"读（全链路 SQL 下推）+ 写（创建强制归属）+ 配置（按校）+ 周期（历史/删除）"四个维度闭合，SCOPE_ALL 不再等于全库。

### 9.2 任务范围（映射设计小节）
| 编号 | 范围 | 落点文件 |
|---|---|---|
| B1 | 4.3 GradeRepository 统计/对比/进步/排名查询统一追加 `and (:schoolId is null or s.schoolId=:schoolId)`，由中央 helper 注入当前 schoolId | `repository/GradeRepository.java` + `RankingService/ComparisonService/TrendService/StatisticsService` |
| B2 | 4.6 历史 `school_id IS NULL` 数据迁移脚本（SQL 正式迁移 + 可选启动回填组件） | `db/migration/V2__backfill_school_id.sql`、`config/SchoolIdMigrationRunner.java` |
| B3 | S2 system_setting 按校隔离（实体 +school_id、组合唯一、读写按校） | `entity/SystemSetting.java`、`repository/SystemSettingRepository.java`、`service/SettingsService.java` |
| B4 | 写路径 schoolId 强制（创建时强制=登录 schoolId；学校创建限 SCOPE_ALL） | `DictionaryService`、`LevelService`、`controller/SchoolController` |
| B5 | 实体外键/级联安全网（删除父级时校验/清理子级，防孤儿越权） | `DictionaryService.deleteClass/deleteCourse`、`LevelService.delete`、`SchoolService.delete`、`ExamService.delete` |

### 9.3 验收标准（可验证断言）
1. **B1-SQL 下推**：不同学校、同考试+同课程下各录成绩；以 A 校老师（SCOPE_ALL 但 schoolId=A）调 `courseStats/comparison/rank/progress`，结果仅含 A 校学生；全局超管(schoolId=null)仍全量。
2. **B2-迁移**：SQL 脚本与回填组件把 `school_id IS NULL` 的 student/grade/exam/course/exam_type 归入配置默认学校；读路径对 null 放开不破坏。
3. **B3-按校配置**：A 校老师改 `parent_rank_visible=false` 只落本校行；B 校仍为全局 false 预期（读回退全局）；同一 key 多校互不覆盖。
4. **B4-写强制**：登录某校老师创建 class/course/exam/examType/level，其 `schoolId==登录 schoolId`；CLASS 老师无法把班级/课程写到他校。
5. **B5-级联安全**：删除被学生引用的班级 → 拒删；删除被 level 引用的年级 → 拒删或清理；学校删除前校验无引用。

### 9.4 兼容与风险
- 数据迁移组件默认**关闭**（`app.migration.backfill-school-id.enabled=false`），避免生产自动改写；正式迁移走 SQL 脚本。
- system_setting 唯一键由 `skey` 升级为 `(school_id, skey)`：`ddl-auto=create` 默认重建表，全局(school_id NULL)兼容。
- B1 仅追加 school 条件、不改分数/满分口径，由既有 `StatisticsMetricTest` 回归。
