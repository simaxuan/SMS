# 三项遗留全面处理交付报告（2026-09-21）

## 一、概述

本交付对应「统一隔离口径」收尾阶段遗留的三项未处理工作（用户要求「对仍未处理的三项进行全面处理」）。三项此前在 MEMORY 中登记为组织关联缺陷的残留项 ①②③：

- ① 前端登录校切换配套——跨校操作必须「切换登录校并重发带目标 schoolId 的 JWT」；
- ② D1-01 物理外键——全部 `*_id` 仅语义裸 LONG，库层无外键约束，靠应用层易产生孤儿数据；
- ③ DataSeeder 给 admin 设非空 schoolId（演示校）——新口径下 admin 被收敛到该登录校，跨校需切换登录校。

两项关键决策已在前期经用户确认：

- **admin 默认登录校口径**：改为 **true-global**（`schoolId=null`，`scope_type=ALL` 即放开全校总览，写路径信任请求体）。
- **物理外键落地方式**：采用**迁移 SQL 脚本**（而非 JPA 注解），实体保持裸 LONG，零启动风险。

## 二、三项改动清单

### 项 1：前端登录校切换配套（后端端点 + 前端切换器）

**后端 `AuthService.java`**

- 构造器新增 `SchoolRepository` 依赖并完成 `final` 字段初始化（修复编译期「可能尚未初始化」）。
- 新增 `switchSchool(Account caller, Long targetSchoolId)`：
  - 权限：`caller.getScopeType()` 非 `SCOPE_ALL` 直接抛 403「仅全局超管可切换登录校」；
  - 校验：若目标校非空，`schoolRepository.findById` 不存在抛 404「目标学校不存在」；
  - 写库：将登录账号 `schoolId` 更新为目标值（可写 `null` 表示「全部学校总览」）；
  - 重签：沿用当前令牌版本号重签 JWT 返回，前端用返回 `user` 刷新会话。
- 审计留痕：记录 `切换登录校 操作者uid=… 目标schoolId=…`。

**后端 `AuthController.java`**

- 新增 `POST /api/auth/switch-school`：从 `LoginUserContext.requireLogin()` 取操作人，解析请求体 `{schoolId}`（可空），调用 `authService.switchSchool`，覆写同名 HttpOnly + SameSite=Lax Cookie，返回 `{token, user}`。

**后端 `SwitchSchoolTest.java`（新增集成测试）**

- 3 个用例：全局超管切到具体校并刷新会话（`user.schoolId==该校`、`token` 非空）；切回总览（`schoolId` 为 null）；非 ALL 账号切换被 403；切到不存在学校被 404。

**前端 `api/index.js`**

- `authApi` 新增 `switchSchool: (schoolId) => http.post('/auth/switch-school', { schoolId })`。

**前端 `App.vue`**

- 用户区新增 `el-select`（仅 `isGlobalAdmin` 可见）：含「全部学校（总览）」`null` 选项，绑定 `activeSchoolId`，`@change` 触发 `onSwitchSchool`。
- `isGlobalAdmin = computed(() => auth.value?.user?.scopeType === 'ALL')`。
- `onMounted` 拉取 `schoolApi.list()` 填充选项；`onSwitchSchool(sid)` 调 `authApi.switchSchool` 并用返回 `user` 经 `setSession` 刷新本地会话（含 schoolId 与重签 token）。

### 项 2：D1-01 物理外键（迁移脚本 `db/migration/V3__add_foreign_keys.sql`）

> 项目未接入 Flyway（`ddl-auto=update` 由 JPA 自动建表，实体保持裸 LONG）。既有 `db/migration/V2__backfill_school_id.sql` 已占用 `V2` 命名，故外键脚本命名 `V3`，为**手工迁移**，不随应用自动执行。

- **0) 孤儿预检**：24 条 `SELECT COUNT` 覆盖 level/class/teacher_class/account/student/parent_student_bind/exam/course/exam_type/grade/exam_course_group 的全部外键列；任一计数 > 0 须先清孤儿再建键。
- **1) 建外键**：`DO $$ … END $$` 包裹、按约束名「已存在则跳过」，可重复执行。ON DELETE 决策：
  - `RESTRICT` 强归属（level↔school、class↔school、account↔school、student↔class/school、exam↔exam_type/school、course↔school、exam_type↔school、grade↔student/school/exam/course）——与现有删除守卫（deleteCourse/deleteExamType/deleteClass 等）一致；
  - `SET NULL` 可选关联（class↔level、student↔parent_owner、exam↔creator、grade↔creator、exam_course_group↔school）；
  - `CASCADE` 纯连接表（teacher_class↔teacher/class、parent_student_bind↔parent/student、exam_course_group↔exam/course）。
- **2) 外键列补索引**：25 条 `CREATE INDEX IF NOT EXISTS`（H2/PG 均支持），提升按外键过滤查询性能。
- **回滚**：文档给出反序 `DROP CONSTRAINT` + `DROP INDEX` 示例。

### 项 3：DataSeeder admin 改 true-global（种子 + 存量脚本 `V4__admin_true_global.sql`）

**`DataSeeder.java`**

- 种子 admin 由 `teacher.setSchoolId(school.getId())` 改为 `teacher.setSchoolId(null)`，注释同步说明统一口径与 `V4` 迁移脚本。

**`db/migration/V4__admin_true_global.sql`**

- `UPDATE account SET school_id = NULL WHERE scope_type = 'ALL' AND school_id IS NOT NULL;` —— 把存量库中历史上经 V2 回填或旧版本创建的 ALL 超管 schoolId 置空，恢复「真全局超管」语义。
- 幂等：新库由 DataSeeder 直接生成 NULL，影响 0 行；重复执行仅对已为 NULL 的行再置空，无副作用。

### 安全加固（主动补闭环）

**`DictionaryService.createClass`**

- 在 `resolveWriteSchoolId` 之后新增空归属校拦截：`if (schoolId == null) throw BizException("请先切换到具体学校后再创建班级，或在请求中指定归属学校")`。

## 四、迁移脚本执行指引（运维 / DBA）

V3、V4 均为**手工迁移**，不随应用自动执行。`publish` 包与开发库均不会自动跑：

1. **备份**：执行前对目标库做全量备份。
2. **V3 步骤**：
   - 先跑「0) 孤儿预检」全部 24 条 SELECT，确认计数全为 0；
   - 若有非零，先评估清理孤儿（或业务确认）再执行建键段；
   - 建键段可重复执行（已存在则跳过）。
3. **V4 步骤**：在备份后执行一次即可（幂等）。若个别 ALL 超管「必须固定归属某校」，请勿执行 V4，改由前端切换器显式设定。
4. **回滚**：分别按文档给出的反序 `DROP CONSTRAINT` / `DROP INDEX` 撤销，删除外键不删数据。

> 注：H2 文件库与 PostgreSQL 生产库的 ADD CONSTRAINT / CREATE INDEX 语法一致，脚本可直接复用于两者。

## 五、风险与注意事项

- **JWT 重签范围**：`switchSchool` 仅在「同版本号」下重签，未触发令牌失效（不 bump token version）。同一账号多端同时在线时，旧令牌仍按旧 schoolId 上下文生效，直至自然过期或被显式失效。当前为单管理员场景，影响可控；若需强一致可后续在切换时 bump version 使旧令牌即时失效。
- **外键 ON DELETE RESTRICT 与现有守卫重叠**：应用层删除守卫（如 `deleteClass` 清 `teacher_class`）与外键 RESTRICT 方向一致，执行 V3 前必须确认无孤儿，否则 RESTRICT 会拒绝建键（这是设计预期，不是缺陷）。
- **V4 影响面**：会把**所有** `scope_type='ALL'` 账号的 schoolId 置空（含历史超管）。若生产环境存在「应固定归属某校的 ALL 超管」，须跳过 V4 并改用前端切换器显式设定。
- **前端切换器依赖登录态刷新**：`onSwitchSchool` 用返回 `user` 刷新 `setSession`；若后端返回结构变更需同步前端。
