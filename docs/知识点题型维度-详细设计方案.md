# 知识点 / 题型维度 · 详细设计方案

> 版本：v1.0（设计交付稿，暂不建表）
> 日期：2026-09-17
> 定位：确认项 4 —— 为后续开发提供可落地的实体、接口与实施步骤，方便后续按此推进。

---

## 1. 背景与目标

当前成绩系统以「学生 × 考试 × 课程」为粒度，仅能刻画"某科某次得多少分"，无法回答：
- 学生某次考试在「代数」「几何」两个知识点上的掌握差异；
- 丢分主要来自「选择题」还是「解答题」；
- 班级整体在哪些知识点上普遍薄弱（教学改进抓手）；
- 同一知识点跨多次考试的掌握度趋势。

本方案在**不破坏现有 granularity（grade 表）**的前提下，新增知识点/题型两个分析维度，为后续实现"诊断式成绩单"打基础。

## 2. 设计原则

1. **分层解耦**：`grade`（总分粒度）保持不变，作为权威总分与排名来源；知识点/题型作为**明细扩展**，通过 `grade_knowledge_point`、`grade_question_type` 关联到 grade。
2. **冗余可控**：允许"只录总分、不录知识点"（录入门槛低）；知识点明细可后补、可部分录入。
3. **派生分析**：知识点掌握度 = 该知识点得分率（得分/该知识点分值），基于明细实时聚合，无冗余统计表。
4. **沿用既有权重体系**：及格/优秀/分布口径与现状一致；知识点只做"掌握度"刻画，不参与总分计算。

## 3. 实体设计（新增 4 张表）

### 3.1 知识点表 `knowledge_point`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 主键 |
| course_id | BIGINT FK→course | 所属课程 |
| name | VARCHAR(64) | 知识点名称（如"整式运算"） |
| parent_id | BIGINT NULL | 父知识点（支持两级，可空） |
| sort | INT | 排序 |
| created_at | DATETIME | |

唯一约束：`(course_id, name)`。

### 3.2 题型表 `question_type`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 主键 |
| name | VARCHAR(32) | 题型（单选/填空/解答…） |
| created_at | DATETIME | |

唯一约束：`name`。

### 3.3 成绩–知识点明细表 `grade_knowledge_point`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| grade_id | BIGINT FK→grade | 关联总分记录 |
| knowledge_point_id | BIGINT FK→kp | |
| score | INT | 该知识点得分 |
| full_score | INT | 该知识点分值 |
| created_at | DATETIME | |

唯一约束：`(grade_id, knowledge_point_id)`，保证同一成绩同一知识点仅一条。

### 3.4 成绩–题型明细表 `grade_question_type`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| grade_id | BIGINT FK→grade | |
| question_type_id | BIGINT FK→qt | |
| score | INT | 该题型得分 |
| full_score | INT | 该题型分值 |

唯一约束：`(grade_id, question_type_id)`。

> 说明：知识点/题型的 `full_score` 之和**不必等于** grade.score，二者是"粗略到精确"的两层视角，允许部分覆盖（如只录了 3 个知识点中的 2 个）。

## 4. 接口设计（新增 controller，老师角色为主）

前缀统一 `/api/analysis`，均 `requireRole(TEACHER)`（家长端接入见 §6）。

### 4.1 基础字典
- `GET /api/analysis/knowledge-points?courseId=` 课程下知识点树
- `POST /api/analysis/knowledge-points` 新增 `{courseId,name,parentId,sort}`
- `DELETE /api/analysis/knowledge-points/{id}`
- `GET /api/analysis/question-types`
- `POST /api/analysis/question-types` 新增 `{name}`

### 4.2 明细录入
- `PUT /api/grades/{id}/knowledge-points` `body:[{knowledgePointId,score,fullScore}]` 覆盖式批量保存该成绩的知识点明细
- `PUT /api/grades/{id}/question-types` `body:[{questionTypeId,score,fullScore}]`

### 4.3 分析查询
- `GET /api/analysis/student-knowledge?gradeId=` 某成绩下该生各知识点得分率（诊断")
- `GET /api/analysis/class-knowledge?examId=&courseId=` 班级各知识点平均得分率（薄弱点 TOP）
- `GET /api/analysis/class-question-type?examId=&courseId=` 班级各题型得分率（如选择题得分率低 → 答题技巧）
- `GET /api/analysis/student-weak?studentId=&courseId=` 个人横向：展示多次考试各知识点得分率折线（趋势）

统一返回形如：
```json
{ "code":200, "data": { "courseId":1, "items":[ {"knowledgePointId":2,"name":"代数","scoreRate":72.5,"count":45} ] } }
```

## 6. 权限与范围约束

- **老师**：管理知识点/题型字典；录入/查看全局明细；分析全校。
- **家长**：**只读**，仅可查看**已绑定孩子**的 `student-knowledge`（沿用 `studentTrend` 的可见规则：teacher 来源只读 + 本人 parent 来源）；不可维护字典、不可录入。
- **来源隔离**：知识点明细挂载在 `grade` 下，天然继承 grade 的 `source` 隔离（teacher/parent 两套明细互不干扰）；统计仅用 teacher 来源。

## 7. 口径说明（防遗忘）

- 知识点得分率 = `SUM(score)/SUM(fullScore)×100`；若某学生该知识点 `fullScore>0` 才计入。
- 班级某知识点得分率 = 全员该知识点得分之和 / 全员该知识点分值之和（人数加权，非简单平均）。
- 满分不一致（如某题 5 分、某题 8 分）已在比值中归一，无需绝对分数线。
- 与 grade 的及格/优秀线互不干扰：知识点只做"掌握度诊断"，不改变总分统计口径。

## 8. 后续可扩展（P2+）

- 知识点难度标签、教学目标达标率；
- 知识点掌握度 → 自动推荐专项练习；
- 题型 × 知识点交叉矩阵（雷达/热力图）；
- 错题本（关联具体小题，需新增"小题/原题"表）。
