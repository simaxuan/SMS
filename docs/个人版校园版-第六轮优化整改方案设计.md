## 0. 现状基线（据当前代码核实，非推测）

| 维度 | 现状 | 缺陷 |
|---|---|---|
| 组织建模 | `class_entity` 仅 `id/name/createdAt`，**无级部、无校园归属** | 问题二（级部/多租户）|
| 统计数据范围 | 老师角色 = **全校**，无组织边界 | 问题二 |
| 家长排名字段返回 | `ranking()` 家长分支返回**全班明细** | 问题一 |
| 学生模型 | `student` 无身份证、无双父母手机号、无来源/校园标记 | 问题三 |
| 账号模型 | `account` 无手机号、无范围、无绑定学校 | 问题三/二 |
| 绑定校验 | 仅「学号+姓名」 | 问题三 |
| 统计口径 | 单科得分率；总分为原始分累加，无标准分/总得分率；无科目组合 | 问题四 |
| 登录 | `username+password` | 问题三（手机号）、微信预留 |

**关键底层事实**：
- `Grade` 实体**无 classId/schoolId 冗余**，班级来自 `Student` join；校园（school）维度需贯穿查询（join 或多级过滤）。
- `class_entity` 无级部/校园字段 → **v4 引入 level 表 + school 表**（用户确认独立表）。

## 2. 问题二：多租户组织建模 + teacher→归属 + 级部排名（v4 全新）

**用户确认**：
- 级部建模 = **独立 `level` 表**；
- **校园也为独立表**（多租户 school）；
- 老师默认 CLASS 可绑多班跨年级；默认按班级过滤，支持级部排名。

### 2.1 新增组织模型（school / level / class 层级）

```sql
-- 校园（多租户根）——用户确认独立表
CREATE TABLE school (
    id          BIGINT PRIMARY KEY,
    name        VARCHAR(128) NOT NULL,
    code        VARCHAR(32)  UNIQUE,   -- 学校编码，多校隔离/认领用
    created_at  TIMESTAMP
);

-- 级部（年级）——用户确认独立表
CREATE TABLE level (
    id          BIGINT PRIMARY KEY,
    school_id   BIGINT NOT NULL,        -- FK -> school.id
    name        VARCHAR(64) NOT NULL,   -- 如 "三年级" / "初二"
    created_at  TIMESTAMP,
    CONSTRAINT uk_school_level UNIQUE (school_id, name)
);

-- 班级挂级部 + 校园（替代 v3 的 class.level 字符串字段）
ALTER TABLE class_entity
    ADD COLUMN level_id BIGINT,          -- FK -> level.id
    ADD COLUMN school_id BIGINT;         -- FK -> school.id
```

**核心**：`school → level → class → student` 四级归属；所有组织数据带 `school_id`，实现**多租户隔离**（这是 v4 相对 v3 的最大变化——从"单库字符串字段"升级为"独立表多租户"）。

### 2.2 全表 school 维度贯穿

以下核心表均需带 `school_id`（或可由上层推导）：

| 表 | school 归属方式 |
|---|---|
| `account` | `+ school_id`（老师/家长所属校）|
| `student` | `+ school_id`（或经 class→level→school 推导，见 2.3）|
| `exam` | `+ school_id`（校内考试归属校）|
| `course` / `exam_type` | `+ school_id` |
| `grade` | 经 `student.school_id` 推导（不加冗余，减少一致性问题）|
| `teacher_class` | 经班级推导 |
| `parent_student_bind` | 经学生推导 |

### 2.3 school 隔离实现（避免每表冗余）—— 已确认方案 A

- **A（已确认）**：`student/exam/course/exam_type/account` 显式带 `school_id`（租户数据源）；`grade/class/teacher_class/bind` 由上层（student/class/account）推导，查询时 join 校验 `school_id` 一致。
- B（全表冗余）：不采纳。

### 2.4 teacher→class 归属 + 级部排名

```sql
CREATE TABLE teacher_class (
    id BIGINT PRIMARY KEY,
    teacher_account_id BIGINT NOT NULL,
    class_id           BIGINT NOT NULL,
    created_at         TIMESTAMP,
    CONSTRAINT uk_teacher_class UNIQUE (teacher_account_id, class_id)
);
```

`account.scope_type`（`CLASS` 默认 / `ALL`）；`DataScopeService`：

```java
Set<Long>   visibleClassIds(Account user);   // CLASS→teacher_class；ALL→null(不限)
Set<Long>   visibleLevelIds(Account user);   // 由可见班级去重 level_id
Set<Long>   schoolId(Account user);          // 当前校
List<Object[]> filterRows(Account u, String scope, List<Object[]> rows, int schoolIdx, int classIdx, int levelIdx);
```

**三级范围** `class`(默认)/`level`/`school`，`ranking/comparison/aggregate` 均支持；`school` 范围仅 ALL。

### 2.5 鉴权边界汇总（v4 多租户）

| 操作 | ALL（本校内）| CLASS（默认）| 家长 |
|---|---|---|---|
| school/level/class CRUD | ✅（本校）| ❌ | ❌ |
| 学生 CRUD | ✅（本校）| ✅ 所属班级 | ❌ |
| 成绩读 | ✅（本校）| ✅ 所属班级 | ✅ 绑定学生 |
| 成绩写/删 | ✅（本校）| ✅ 所属班级 | ✅ 绑定学生 parent |
| 统计/排名 | ✅ 本校三级范围 | ✅ 班级/级部 | ✅ 绑定学生 |
| 系统设置 | ✅（本校）| ❌ | ❌ |
| 跨校访问 | ❌（school_id 强隔离）| ❌ | ❌ |

> **多租户要点**：任何跨校访问必须被 `school_id` 校验拒绝；`account/student/exam/course/exam_type` 的写入须归属当前 `school_id`（从登录上下文取，不信任请求体）。

## 3. 问题三：家长绑定 + 身份证 + 默认密码 + 双父母 + 微信预留（v4 已确认）

**用户确认**：
1. 身份证 **AES 加密**存储；身份证后 8 位**加密存入密码字段**。
2. 短信通道**预留**（本期不用验证码）。
3. 双父母编辑按推荐方案。
4. 登录：学生姓名 + 手机号 + 密码（沿用）。
5. 自建学生标记 merged（沿用）。
6. **v4 新增：默认密码无须强制首改**（考虑双父母各自改密会导致对方无法登录）。
7. **v4 新增：微信登录充分考虑，本期不做，预留**。

### 3.1 Student 模型（更新）

| 字段 | 存储 |
|---|---|
| `id_card` | **AES 加密**（255）|
| `id_card_hash` | BCrypt(后 8 位) |
| `father_phone`/`mother_phone` | VARCHAR(20) |
| `origin` | school/self |
| `parent_owner_account_id` | BIGINT |
| `enrolled`/`merged` | BOOLEAN |
| `school_id` | BIGINT（v4 新增）|

### 3.2 默认密码策略（v4 修正：不强制首改）

**背景（用户确认）**：双父母各一账号，默认密码均为该生身份证后 8 位。若**强制首改**，一方改密后另一方未被告知，将无法用默认密码登录 → 锁死家庭另一半。因此：

- **默认密码 = 身份证后 8 位（BCrypt 入 password_hash），不强制首改**。
- 家长可**自愿**修改密码（系统提供"修改密码"入口）；改密后的账号用新密码登录。
- **双父母协同（v5 确认：恢复默认密码仅由老师操作）**：
  - 改密成功页**明示提示**"请告知另一位家长新密码"。
  - 若家庭一方锁死/忘记改后密码，**不开放家长自助"恢复默认密码"**（避免家长可绕过密码策略重置他人密码）。
  - **恢复密码统一由老师端操作**：老师（教务/管理员）在学生详情/家长绑定管理中对对应家长账号执行"重置为默认密码"（=该生身份证后 8 位），需老师身份鉴权 + 操作审计留痕。
- `account.last_password_change` 时间戳作审计。

### 3.3 绑定校验（四要素 + 默认密码）

`BindRequest { studentNo, name, phone, idCardLast8, relation, password }`：① 学号+姓名 ② idCardLast8 比对（hash）③ phone 与父/母手机号匹配 ④ relation 口径一致 ⑤ 建立绑定 + 设置默认密码（后 8 位哈希）。

### 3.4 双父母：信息/编辑一致（沿用 confirmed）

- 双账号各绑定同一学生，信息一致、编辑能力一致（可编辑绑定学生全量 parent 成绩，teacher 只读），保留 `creator_account_id` 审计。

### 3.5 手机号 + 登录 + 微信预留（v5 确认）

- `account.phone`（唯一）作登录名；本期登录 = 手机号 + 密码 + **失败锁定（固定 5 次/15 分钟，v5 确认硬编码不配置化）**。
- **短信预留**：字段/接口占位，后续接服务商加验证码强因子，不改模型。
- **微信登录预留（v5 确认：仅接口占位）**：
  - `account` 预留 `wechat_openid VARCHAR(64)`、`wechat_unionid VARCHAR(64)`、`auth_type VARCHAR(16)`（`password`/`wechat`/`phone`）字段；`account_auth` 子表扩展位（一账号多登录方式）留待后续。
  - **本期仅保留 `POST /api/auth/wechat` 接口占位（返回"未启用"）**，不实现鉴权逻辑，不做绑定引导 UI。
  - 预留字段仅建 schema，不纳入登录流程。

### 3.6 个人版自建学生与入学对接（沿用 v2/v3 + school 适配）

- 家长自建 `origin=self, enrolled=false` 学生（归属家长 `school_id` 或 null=未入学无校）。
- 认领合并：学校建档后用「学号+姓名+手机号+身份证后8位」命中 → 自测成绩迁移到校园版学生（保留 source=parent）+ 正式绑定；自建记录 `merged=true`。
- 迁移仅限同一 `id_card`（密文比对），幂等 + 事务；并入 `school_id` 一致性校验。

## 4. 问题四：总分口径 + 标准分权重（v4 已确认）

**用户确认**：标准分默认 `equal`，**本期即开放 `custom-weighted`**。

### 4.1 三口径并存（沿用）

- 总分 `totalScore=Σscore`（主展示）；总得分率 `totalPercent=Σscore/Σfull×100`（跨考试）；标准分 `stdScore`（跨科定位）。

### 4.2 标准分权重模型（v4）

| 模式 | 计算 | 开放 |
|---|---|---|
| `equal`（默认）| `mean(各科 score/full×100)` | ✅ |
| `full-weighted` | `Σscore/Σfull×100`（=总得分率）| ✅ |
| `custom-weighted`（v4 开放）| `Σ(得分率×w_i)/Σw_i`，权重量可配置 | ✅（本期）|

- 系统设置 `KEY_STD_WEIGHT_MODE`（equal/full-weighted/custom-weighted）+ `KEY_STD_WEIGHTS`（科目权重 JSON）。
- **边界（防失真）**：缺考/无效科目不进分母；`full<=0` 不计；空数据 `stdScore=null`；单科退化；前端标注"基于 n 科按 × 权计算"。
- 默认 `equal`，`custom-weighted` 本期开放（用户确认）；`full-weighted` 时 stdScore≡totalPercent。

### 4.3 多科总分分析

- `exam_course_group`（exam_id, course_id, active, 可含 school_id）承载科目组合，默认全科可配。
- 输出 `totalScore/totalFull/totalPercent/stdScore`；前端恒显满分"92/120"。

## 7. 欠考虑点补充分析（v4 更新）

### 7.1 多租户（school）——本次最大新增
- **school_id 一致性**：跨表 join 须校验 school 一致，防"成绩/统计误串校"；`account`/`student`/`exam` 写入归属取登录上下文，**不信任请求体 schoolId**。
- **数字隔离 vs 物理隔离**：v4 为单库内 `school_id` 逻辑隔离（多校共享一套实例）；若后续多校需物理隔离，逐库部署即可（与 v3 结论一致，但新增了 school 表为逻辑隔离铺路）。
- **教师/家长登录先定位 school**：登录后按账号 school 带入上下文，未绑定学校（如新家长）引导选校/绑校。

### 7.2 密码与安全（v5 确认）
- 不强制首改 → 默认密码长期存在 → 需**失败锁定**防爆破（已确认硬编码 5 次/15 分钟）。
- 双父母改密冲突：**恢复默认密码仅由老师操作**（老师身份鉴权 + 审计留痕）；家长自助不开放，防绕过密码策略。
- 身份证 AES 密钥管理（`APP_CRYPTO_KEY`，演示内置+README 置换）；`id_card_hash` BCrypt(后8位)避免明文中间态。

### 7.3 微信预留
- `account` 预留 openid/unionid/auth_type + `account_auth` 子表扩展位；**本期仅 `POST /api/auth/wechat` 接口占位（返回"未启用"）**，不做鉴权与绑定 UI。

### 7.4 权限语义
- 双父母编辑一致需审计（creator）+前端"编辑人"提示。
- CLASS 老师跨级部时 `visibleLevelIds` 限所属班级上位级部，**禁止**扩到非所属级部。
- school 隔离：跨校访问一律拒绝（含统计/导出）。

### 7.5 数据一致性与迁移
- `teacher_class`/CLASS 至少绑一班否则空视图 → 归属初始化/提示。
- 自建→认领迁移：幂等+事务+同 id_card 唯一约束+school 校验。
- 双父母并发编辑：最后写入或乐观锁（H2 演示可接受）。

### 7.6 统计口径认知
- 标准分/总得分率并存易混淆 → 默认只展「总分+总得分率」，标准分高级展开；恒显满分。
- 级部排名标注"基于 n 个班级"。

### 7.7 前端/部署
- 沿用 echarts/core 按需引入（防 818KB 回归）。
- 多租户前端：登录后按 school 过滤下拉（班级/级部/科目组）。
