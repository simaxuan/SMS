# 启动器运行环境自检与自愈设计（2026-09-18）

> 针对 `tools/ServerLauncher.cs`（WinForms 单机启动器）增强：启动时自动检查前后端运行环境是否完整；
> 环境缺失或不完整时**自动发现并配置**可用的后端运行时；全程输出结构化、可追溯的日志（环境检查结果 / 加载过程 / 启动状态）。

## 一、部署模型与“运行环境”的判定口径

本项目采用 **单 jar 全栈包**：`publish.ps1` 将前端 `dist/` 打包进后端 jar 的
`BOOT-INF/classes/static/`，Spring Boot 直接伺服前端页面。因此：

| 环境维度 | 判定对象 | 就绪标准 |
|---|---|---|
| **后端运行时** | Java（`java.exe`） | 存在且 `java -version` 主版本 **≥ 21**（与 `pom.xml` 编译目标一致） |
| **前端运行时** | jar 内静态资源 | jar 内含 `BOOT-INF/classes/static/index.html`（前端已内嵌），否则仅后端可用、无页面 |
| **应用包** | jar 文件 | 存在、非空、为合法 zip（`PK` 头） |
| **端口** | 网络监听 | `port` 未被占用（防旧进程残留 / 端口冲突导致静默失败） |

> 说明：单 jar 部署下前端不在运行时依赖 Node，故“前端环境”= **jar 内是否已内嵌前端静态资源**；
> 若发布时用了 `-Dfrontend.bundle.skip=true`（未内嵌），启动器会明确 WARN 并提示。

## 二、环境自检流程（启动即执行）

启动器构造早期调用 `RunSelfCheck()`，逐项输出 **`[ENV]`** 日志并汇总。

1. **应用包检查**：jar 是否存在、非空、是否为 zip 魔数开头。
2. **前端内嵌检查**：打开 jar(zip)，查找入口 `BOOT-INF/classes/static/index.html`。
3. **后端运行时探测**（多源择优，按优先级）：
   1. `launcher.ini` 显式 `java=<路径>`；
   2. 启动器同级便携运行时 `runtime\` / `jre\`（自动加载**随包携带**的 JRE）；
   3. 环境变量 `JAVA_HOME\bin\java.exe`；
   4. `PATH` 中的 `java`；
   5. 常见安装目录：`%ProgramFiles%\Java`、`Eclipse Adoptium`、`Microsoft\jdk-*`、`Zulu`、`Amazon Corretto`、`BellSoft` 等（按版本降序择优）。
   - 对每个候选执行 `java -version` 解析主版本，选首个 **≥ 21** 者；对版本过低候选给出 WARN 并继续。
4. **端口占用预检**：`TcpListener` 绑定测试；被占用 → WARN（提示可能存在残留进程，可先访问或手动停）。
5. **自愈项**（见下）与**汇总**：`canStart = jarOk && javaOk`，据此启用/禁用「启动服务器」按钮。

## 三、自动加载 / 配置缺失环境（自愈）

| 场景 | 自愈动作 | 说明 |
|---|---|---|
| JAVA_HOME 未设 / PATH 无 java，但常见目录有 | **自动选用**该 java 绝对路径启动 | 不依赖系统 PATH，实现“自动配置环境” |
| 用户希望**随包携带** JRE | 放置 `runtime\jre\bin\java.exe`（或 jdk）到启动器同级 | 启动器自动优先使用；离线可自愈 |
| 完全无 Java 且 `auto-download-jre=true` | **联网自动下载**便携 JRE 到 `runtime\` 并解压使用 | 默认关（避免无网络下卡顿）；见 `launcher.ini` |
| jar 未内嵌前端 | WARN + 清晰提示，后端照常可启 | 属发布配置问题，运行时不强行修复 |
| 端口被占用 | 默认 WARN；`port-auto-fix=true` 时可自动顺延下一空闲端口 | 可选 |

> `auto-download-jre` 默认**关闭**（避免无网环境卡顿）；`port-auto-fix` 默认**开启**（端口占用时自动顺延下一空闲端口，避免启动失败）；二者均为 launcher.ini 可选开关。

## 四、日志记录（详细、结构化、可追溯）

- **落盘**：`logs\server-YYYYMMDD.log`（UTF-8，追加式）与 UI 同步。
- **自检段**：`[ENV]` 前缀，逐项 `[通过]/[警告]/[失败]`，含判定对象、实际值与路径。
- **加载段**：`java 探针命令`、所选运行时路径与版本、便携/下载运行时加载过程每步日志。
- **启动段**：完整 `java -jar ...` 启动命令、进程 PID、**健康轮询**（每 2s 一次 GET 根路径，记录尝试次数），
  服务响应任意 HTTP 状态（含 4xx/5xx）即视为进程已就绪 → 输出「✔ 服务器已就绪，端口 x」；
  超时/退出则输出退出码与最后 stderr，方便定位。

## 五、`launcher.ini` 新增可选键

```
java=<显式 java.exe 路径>            # 最高优先级运行时
java-min-version=21                 # 最低主版本（默认 21）
auto-download-jre=false             # 无 java 时是否联网下载便携 JRE（默认关）
auto-jre-url=https://api.adoptium.net/v3/binary/latest/21/ga/windows/x64/jre/hotspot/normal/eclipse
port-auto-fix=false                 # 端口占用时自动顺延（默认关）
```

## 六、交付与验证

- 重写 `tools/ServerLauncher.cs`；更新 `publish.ps1`（可选打包 `tools\runtime` 便携 JRE 到 `publish\runtime`、
  写入上述默认配置、README 更新）。
- 验证：用 csc 编译通过 → 启动器在无 JAVA_HOME/PATH 时仍能经由常见目录/便携运行时找到 Java；
  `[ENV]` 自检日志齐全；前端内嵌缺失时 WARN 且后端可启；端口占用可被预检。
