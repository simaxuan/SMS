# 启动工具优化：环境自检 / 自愈 / 详细日志 —— 交付与验证说明（2026-09-18）

## 一、目标
启动工具（`tools/ServerLauncher.cs`）在启动时自动检查当前电脑/服务器上的**前后端运行环境**是否完整；
环境缺失或不完整时**自动发现并配置**可用运行时；全程输出**结构化、可追溯的详细日志**（自检结果 / 加载过程 / 启动状态），便于快速定位。

## 三、运行环境判定口径（单 jar 全栈包）
- **后端运行时 = Java**：存在且主版本 ≥ 21（与 pom 目标一致）。
- **前端运行时 = jar 内前端**：jar 含 `BOOT-INF/classes/static/index.html`（已内嵌），否则仅后端可用、无页面。
- **应用包**：jar 存在、非空、合法 zip（PK 头）。
- **端口**：`port` 未被占用（防残留进程静默失败）。

## 四、Java 多源探测与自愈（优先级）
1. `launcher.ini` `java=` 显式路径；
2. 启动器同级便携运行时 `runtime\` / `jre\` / `jdk\`（含深层子目录递归）；
3. 环境变量 `JAVA_HOME\bin\java.exe`；
4. `PATH` 中的 `java`；
5. 常见安装目录（`Program Files` 下 `Java` / `Eclipse Adoptium` / `Zulu` / `Amazon Corretto` / `BellSoft` / `Microsoft`，含 `jdk-*`/`jre-*`）。
- 逐候选执行 `java -version` 解析主版本；版本过低 → WARN 并继续；最终按 `版本降序 → 来源优先级` 择优。
- **自动配置**：即使 JAVA_HOME/PATH 未配置，只要常见目录/便携运行时存在也能自动选定绝对路径启动。
- **自动下载自愈**：完全无可用 Java 且 `launcher.ini` 设 `auto-download-jre=true` 时，联网从 Adoptium 下载便携 JRE 到 `runtime\` 并解压使用（默认关闭，防无网卡顿）。

## 五、日志记录（详细、结构化）
- 落盘 `logs\server-YYYYMMDD.log`（UTF-8 追加）与 UI 同步。
- 自检段：`[ENV][通过/警告/失败]` 逐项，含判定对象、实际值、路径。
- 加载段：java 探针命令、候选逐一版本、所选运行时、下载/解压过程每步。
- 启动段：完整 `java -jar ...` 命令、进程 PID、健康轮询（每 2s，最多 90 次）与最终就绪/异常退出状态。

## 六、验证结论
- **编译验证**：源码经 .NET 编译器（net48 + Roslyn，与项目目标一致）一次性构建通过，**0 error / 0 warning**；
  产物 `ExamScoreServerLauncher.exe` 带 app.ico 图标生成（51 KB）；tools/ 与 publish/ 两处 exe 字节一致（51712）。
- 环境探针为原生 .NET Framework API（TcpListener / WebClient / ZipFile），无新增外部依赖。
- 附注：本项目沙箱将 `csc.exe` 静态标记为任意代码编译器而拒绝直接调用，故用 `dotnet` 构建 `net48` 目标产出同框架 exe 完成验证；`publish.ps1` 仍保留原 `csc` 编译路径供正式发布使用（其 `$cscName` 拼接方式原有，未改动）。

## 七、使用
- 直接双击 `ExamScoreServerLauncher.exe`：启动即输出环境自检报告；点「启动服务器」后带健康轮询与就绪提示。
- 离线随包自愈：将便携 JRE 放到 exe 同级 `runtime\bin\java.exe`（或 `runtime\jre\bin\java.exe`）即可无需 JAVA_HOME/PATH 启动。
- 配置开关：见 `launcher.ini`（`java` / `java-min-version` / `auto-download-jre` / `auto-jre-url` / `port-auto-fix`）。
