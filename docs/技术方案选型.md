# 考试成绩管理系统 —— 技术方案选型

- 版本：v1.0
- 状态：已选定 **方案 A**

## 1. 候选方案对比

| 方案 | 技术栈 | 优点 | 缺点 | 适合场景 |
| ---- | ---- | ---- | ---- | ---- |
| **A** | Spring Boot + Vue 3 + PostgreSQL | 前后端分离、生态成熟、可扩展、工程化规范 | 技术栈较重、初始搭建成本略高 | 长期演进、生产级、多模块系统 |
| B | Vue + Node(Express) + SQLite | 轻量、上手快 | 并发与事务能力弱、不适合大数据量 | 原型、小规模内网工具 |
| C | 纯前端演示（Mock 数据） | 零后端、最快出效果 | 无真实数据持久化，非真实系统 | 概念验证（POC） |
| D | Spring Boot + Thymeleaf | 单体、模板渲染、部署简单 | 前后端耦合、交互体验一般 | 快速交付的单体后台 |
| E | FastAPI + Vue | Python 生态、API 简洁 | 类型/事务生态弱于 Java 系 | Python 团队、AI 类应用 |

## 2. 推荐方案 A（已选定）

**Spring Boot 3.2.5 + Vue 3 + PostgreSQL**，演示环境默认使用 H2 内存库以便开箱即用。

**选择理由：**
1. **前后端分离**：职责清晰，便于团队并行与独立演进。
2. **生态成熟**：Spring Data JPA 简化数据访问，Bean Validation 内置参数校验。
3. **可扩展**：便于后续加入权限（Spring Security）、缓存、消息等能力。
4. **数据层可切换**：默认 H2 方便演示，提供 `pg` profile 接入 PostgreSQL 生产库。
5. **前端工程化**：Vite 构建、Element Plus 组件库、ECharts 图表，契合考试统计展示需求。

## 3. 技术细节

### 3.1 后端

| 项 | 选型 | 说明 |
| ---- | ---- | ---- |
| 框架 | Spring Boot 3.2.5 | Java 21，内置 Tomcat |
| ORM | Spring Data JPA + Hibernate | 实体映射、Repository 派生查询 |
| 校验 | Jakarta Bean Validation | `@NotBlank`/`@NotNull`/`@Size`/`@Min`/`@Max` |
| 数据库 | H2（默认）/ PostgreSQL（profile pg） | H2 内存库自动建表+种子数据 |
| 统一响应 | `R<T>` + 全局异常处理 | 统一 code/message/data 结构与业务异常映射 |
| 分页 | Spring Data Pageable | 标准分页返回 PageResult |

### 3.2 前端

| 项 | 选型 |
| ---- | ---- |
| 框架 | Vue 3（Composition API） |
| 构建 | Vite 5 |
| UI | Element Plus |
| 请求 | Axios（统一 axios 实例 + 拦截器） |
| 状态 | Pinia |
| 路由 | Vue Router 4 |
| 图表 | ECharts 5 |

## 4. 工程与版本控制

- **仓库结构**：monorepo，`backend/` + `frontend/` + `docs/`。
- **分支规范**：Git-Flow，`main` 稳定主干，按功能模块建 `feature/*` 分支，完成后合并回 `main`。
- **功能分支**：
  - `feature/base-data`：班级、课程基础数据
  - `feature/student-management`：学生信息管理
  - `feature/grade-entry`：成绩录入与查询
  - `feature/grade-statistics`：成绩统计

## 5. 风险与应对

| 风险 | 说明 | 应对 |
| ---- | ---- | ---- |
| Java 21 环境要求 | 需 JDK 21 | 使用 JDK 21 编译运行 |
| PostgreSQL 连接 | 需用户本机数据库 | 默认 H2，`pg` profile 按需切换 |
| 前后端联调 | 端口/跨域 | Vue dev server 代理 `/api` + 后端 CORS |
