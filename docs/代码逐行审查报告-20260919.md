## 二、已亲自核验的关键事实（P0 级，确属真实缺陷）

1. `backend/.../config/ProductionGuard.java:51-53` —— 门禁判定 `activeProfiles` 是否含 `"prod"`，但生产配置文件名为 `application-pg.yml`（激活的是 `pg`），**门禁永不触发**。✅ 已读源码确认。
2. `tools/ServerLauncher.cs:851` —— 启动参数仅 `--server.port=...`，**从不传 `--spring.profiles.active=pg`**；`application-pg.yml` 真实存在却永不被加载。✅ 已读源码 + Glob 确认。
3. `backend/.../repository/StudentRepository.java:29-36` 与 `ExamRepository.java:13/15/18` —— 学生/考试列表查询**完全没有 `school_id` 过滤**。✅ 已读源码确认。
4. `frontend/src/views/Settings.vue:10` —— `@change="save('parent_rank_visible', parentRankVisible.value)"`，在 `<script setup>` 模板里 `parentRankVisible` 已被自动解包，`parentRankVisible.value` 恒为 `undefined`，而 `save()` 第 72 行 `if (value === undefined) return` 直接丢弃 → 排名开关/档位**永远存不进库**。✅ 已读源码确认。
5. `backend/.../service/RankingService.java:63-122` —— 老师分支中 `scope`（class/level/school）仅在第 98 行被"原样写回结果"，**从未用于过滤/分组**；底层 `rankRows` 也无 school 约束。✅ 已读源码确认。

## 四、第一类：功能模块实操衔接断层（流程断点）

### PM-①【严重 / P0】老师/管理员账号无自建入口
- **位置**：`backend/.../controller/AuthController.java:30`（`/register` 强制 `role=PARENT`）；`AuthService.register`；`config/DataSeeder.java:225-232`（仅 seed `admin/admin123` 且 `SCOPE_ALL`）；前端无老师/管理员创建界面。
- **现象**：系统里没有任何创建老师或管理员账号的 API/界面。生产配置 `seed=false` 后，第一位老师/管理员无从产生 → 考试创建、成绩录入、统计等**教师主流程完全不可达**，产品实质依赖演示账号。
- **建议**：提供"首位管理员初始化向导"或在组织管理增加"教师管理"tab（创建/停用/重置密码），创建时强制 `schoolId`+`scopeType`。

### PM-②【高 / P1】家长认领/自建孩子前端无入口
- **位置**：`backend/.../controller/ParentController.java:31`（`/claim`）、`:38-44`（`/students` 自建）；`frontend/src/api/index.js` 的 `parentApi` 仅有 `bind/unbind/preference`；`parent/ParentBind.vue` 仅做 bind。
- **现象**：后端已支持"认领已有孩子""自建学生"，但家长端界面完全不可达，属"已实现未接线"的功能孤儿。
- **建议**：在 `ParentBind.vue` 增加"认领/申请关联"与"自建孩子"入口；若决定不做则删除后端孤儿端点。

### PM-③【高 / P1】学生规模硬截断 100 条
- **位置**：`frontend/src/views/GradeEntry.vue:241`、`GradeQuery.vue:122`、`StudentTrend.vue:129` 均 `studentApi.list({ size: 100 })`。
- **现象**：班级/范围学生数 >100 时，超出学生无法被选择、录入、查询或展示趋势，造成数据漏选。
- **建议**：仿 `StudentList.vue` 的 `page/size` 分页或关键字懒加载，或按班级维度拉全量，并确认后端分页上限。

### PM-④【高 / P1】多科「科目组合/总分」后端已实现、前端无接线
- **位置**：`backend/.../controller/ExamController` 的 `/exams/course-groups` 端点；`frontend/src/api/index.js:34-35` 定义了 `courseGroups/saveCourseGroups` 但无任何 `.vue` 调用；`Statistics.vue` 学生总分 `loadStudentStat` 未传 `examCourseGroupId`。
- **现象**：核心卖点"多科组合加权标准分/总分"仅写契约测试、界面无配置/使用入口，对用户不可见不可用。
- **建议**：统计/设置页提供"科目组合"配置 UI 并传 `examCourseGroupId`；若暂不做则移除后端孤儿端点与契约测试。

### PM-⑤【中 / P2】班级创建入口与老师-班级归属跨模块分散、初始化顺序依赖
- **位置**：`frontend/src/views/Organization.vue`（无班级创建）vs `Dictionary.vue`（班级实际创建入口）；`Organization.vue:211` 归属下拉依赖基础数据已建班级。
- **现象**：新手在"组织管理"找不到建班级入口；老师-班级归属下拉依赖前置已建班级，初始化存在隐式顺序依赖，流程易卡住。
- **建议**：在组织管理聚合"学校→级部→班级→老师归属"完整链路，或增加"班级"tab。

### PM-⑥【中 / P2】创建考试可不带考试类型 → 统计口径漂移
- **位置**：`backend/.../dto/ExamRequest.java`（`examTypeId` 可选）；`ExamController/ExamService` 允许无类型的考试。
- **现象**：考试类型未初始化仍可创建考试，后续"学期+课程"统计依赖 `exam.semester/type`，缺省值让学期维度为空或口径漂移。
- **建议**：创建考试强制选择类型或前置校验"请先初始化考试类型"。

### PM-⑦【中 / P2】前端登录后从不调用 `/auth/me` 校准会话
- **位置**：`backend/.../controller/AuthController.java:67`（`/me` 已实现）；`frontend/src/composables/useAuth.js`、`Login.vue`、`api/http.js`（仅缓存登录响应快照、刷新不重新校验）。
- **现象**：角色/学校/权限变更或 token 信息不全时前端状态失真，刷新不重新对齐。
- **建议**：启动与登录后调用 `/auth/me` 校准，路由守卫据此动态决定可见菜单。

### PM-⑧【中 / P2】班级/课程字典列表未按学校隔离（跨租户可见）
- **位置**：`backend/.../service/DictionaryService.java:45-47`（`listClasses=findAll`）、`:96-98`（`listCourses=findAll`）；所有 `dictApi.classes()` 调用方均收全量。
- **现象**：A 校老师能在下拉看到 B 校班级/课程名称（信息泄露）。
- **建议**：改为 `findBySchoolId(LoginUserContext.getSchoolId())`，或明确"基础数据共享"并写入文档由前端兜底过滤。

### PM-⑩【低 / P2】注册成功不自动登录
- **位置**：`frontend/src/views/Login.vue`（注册成功仅提示"请登录"）。
- **现象**：注册（仅家长）后需手动再登录，体验断层。
- **建议**：注册成功后以返回账号自动登录并跳转家长首页。

## 五、第二类：功能选项异常（逻辑错误 / 配置矛盾 / 选项缺失）

### F1【严重 / P0】Settings 排名开关/档位完全失效（已核验）
- **位置**：`frontend/src/views/Settings.vue:10`（开关）、`:15`（下拉）；`save()` 第 72 行 `if (value === undefined) return`。
- **现象**：`<script setup>` 模板里 `parentRankVisible` 已被自动解包，`parentRankVisible.value` 恒 `undefined` → 两个最核心控件看似可点，实则**永不入库**。刷新或被后端回滚后还原。
- **建议**：改为 `@change="(v)=>save('parent_rank_visible', v)"` 与 `@change="(v)=>save('parent_rank_detail', v)"`，下拉同理用回调参数。

### B1【严重 / P0】ProductionGuard 判定 `prod` 但生产用 `pg`，门禁永不触发（已核验）
- **位置**：`backend/.../config/ProductionGuard.java:51-53`（`anyMatch("prod")`）；实际配置 `application-pg.yml`（profile `pg`）。
- **现象**：所谓"生产门禁"（默认密钥、H2 禁止、seed 关闭）因 profile 名不匹配而**永远不触发**，保护网形同虚设。
- **建议**：判定改为 `pg`（或兼容 `prod/pg`）；确保 `application-pg.yml` 与激活名一致；启动器支持激活 profile。

### B2【严重 / P0】启动器从不激活 `pg` → 实际跑 H2 内存库（已核验）
- **位置**：`tools/ServerLauncher.cs:851`（仅 `--server.port`，无 `--spring.profiles.active`）；`publish/launcher.ini` 无 profile 键；`LoadConfig` 仅识别 port/jar/jvm/java/auto-* / port-auto-fix。
- **现象**：启动器定位是"单机生产服务器"，但默认 profile 走 `application.yml` → **H2 内存库（`create-drop`，重启即丢全部数据）+ seed 默认 true + 默认密钥 + H2 控制台开启**，与生产目标直接矛盾，且与 B1 互为因果。
- **建议**：启动参数增加 `--spring.profiles.active=pg`（或 ini 增加 `profile=` 键）；发布包确保 `application-pg.yml` 与 PostgreSQL 凭据就位；否则把默认 profile 指向生产。

### C3【严重 / P0】启动器/ini 无 profile 选项（配置缺失，关联 B2）
- **位置**：`tools/ServerLauncher.cs:199-206`（LoadConfig 键集合）、`publish/launcher.ini`。
- **现象**：用户无法通过启动器选择"生产/PostgreSQL"模式。
- **建议**：增加 `profile=` ini 键并拼 `--spring.profiles.active=`。

### B3【高 / P1】`application-pg.yml` 未覆盖 `app.seed.enabled`
- **位置**：`backend/src/main/resources/application-pg.yml`（全文无 `app.seed.enabled`）；对照 `application.yml:36`（默认 true）、`ProductionGuard.java:75`（要求 false）。
- **现象**：即便激活 pg，`seed.enabled` 仍取默认值 true，演示数据会写入"生产"库；且因 B1 门禁不触发，脏数据 + 默认密钥并存。
- **建议**：`application-pg.yml` 显式 `app.seed.enabled: false`；或 `application.yml` 默认改 false，仅开发环境用环境变量开启。

### B6【高 / P1】默认密钥在单机部署实际生效
- **位置**：`JwtUtil.java:39`（`local-demo-secret-...`）、`AesCrypto` 默认密钥、`ProductionGuard` 演示密钥常量。
- **现象**：默认密钥仅"本地/H2 演示"可用，但如 B1/B2 所述单机部署既不激活 pg 也不触发门禁，**默认 JWT/AES 密钥在生产实例真实生效**，可伪造 token / 解密身份证。
- **建议**：配合 B1/B2，强制注入 `APP_SECURITY_TOKEN_SECRET` 与 AES 密钥；或安装流程生成随机密钥写入配置。

### F2【高 / P1】统计「学生总分」Tab 学生下拉损坏
- **位置**：`frontend/src/views/Statistics.vue:419-420,429,143-145`。
- **现象**：`studentApi.list()` 不传参（后端默认 `size=10`），且把 `PageResult` 对象直接当数组 `students.value = st || []` → 下拉出现 4 个垃圾选项、无法预选。
- **建议**：`students.value = (st && st.content) || []` 并显式传大 `size` 或分页。

### F3【高 / P1】统计「成绩预警」与「成绩排名」Tab 共用同一查询对象
- **位置**：`frontend/src/views/Statistics.vue:206,211,278,361`。
- **现象**：预警 Tab 的考试/课程选择器直接绑定排名 Tab 的 `rankQuery`，两 Tab 状态强耦合；预警 Tab 无独立 scope 却透传排名 Tab 的 scope；初进无数据需手动再改一次。
- **建议**：预警 Tab 用独立 `reactive` 对象；`onTabChange` 主动触发 `loadWarn`。

### F4 / O1【高 / P1】老师端「排名范围」(class/level/school) 后端忽略（已核验）
- **位置**：`frontend/src/views/Statistics.vue:108-112` ↔ `backend/.../service/RankingService.java:98-122`。
- **现象**：前端提供三档 scope，后端老师分支**完全忽略 scope**，仅按 DataScope 收口后全量赋名次；选"年级/全校"与"班级"输出完全一致。
- **建议**：后端按 scope 分组/裁剪（class→按 classId；level→按级部；school→按 schoolId），均叠加当前 school 约束。

### D4【高 / P1】家长成绩列表后端未隔离（越权边界）
- **位置**：`frontend/src/views/parent/ParentEntry.vue:91-92`（前端按 `source==='parent'` 过滤）↔ 后端 `GradeController`/`GradeRepository`（按学生返回**全部来源**成绩）。
- **现象**：家长成绩接口把该学生 teacher 来源成绩一并下发到浏览器，仅靠前端隐藏 → 隐私/越权边界问题。
- **建议**：后端按当前家长账号 + 绑定关系，仅返回 `source='parent'` 或经授权的成绩。

### F5 / B5【中 / P2】家长排名分母显示为 `/1`
- **位置**：`frontend/src/views/parent/ParentTrend.vue:79` ↔ `RankingService.java:194-202`（`total=selfList.size()`）。
- **现象**：`total` 应为范围总人数（`mine.size()`），却取本人行数，显示"名次 5 / 1"；且 aggregate 承诺的班级聚合 `classAgg` 前端未渲染。
- **建议**：后端 aggregate/limited 下把 `total` 改为 `mine.size()`；前端渲染 `classAgg`。

### F6【低 / P2】注册模式单选「老师」可点但被拒
- **位置**：`frontend/src/views/Login.vue:7-10,63-66,95-98`。
- **现象**：注册时强制 `role=PARENT` 但 `el-radio` 仍可点"我是老师"，提交才拦截。
- **建议**：注册模式下 `disabled` 该选项，从源头避免歧义。

### F7【中 / P2】学生下拉写死 `size:100`（同 PM-③）
- **位置**：`frontend/src/views/GradeEntry.vue:241` 等。
- **建议**：分页/关键字检索，避免写死 100。

### F9【低 / P2】成绩录入未校验 分数 ≤ 满分
- **位置**：`frontend/src/views/GradeEntry.vue:24,27,165-167`。
- **现象**：可录入分数大于满分（如满分 100 录 150），后端未强制。
- **建议**：前端 `:max="fullScore"`，后端保存时校验。

### C1【低 / P2】port-auto-fix 顺延后状态栏端口标签不更新

## 六、第三类：数据层 / 多租户一致性（运营异常根因）

### S1【严重 / P0】无 teacher 账号创建 API 且 schoolId 恒 null（已关联 PM-①）
- **位置**：`AuthController/AuthService/SchoolController` 全量扫描；`AccountRepository` 无按 school 建 teacher 的方法。
- **现象**：生产只能靠 seed admin（SCOPE_ALL、schoolId=null）登录；无法为各学校创建归属正确的 teacher → M3/M6/M7 隔离前提完全失效，**系统实际无法以多租户方式运转**。
- **建议**：新增 teacher 管理接口，创建时必填 `schoolId` 与 `scopeType` 并同校校验。

### M1/M2/M3【严重 / P0】考试/学生/字典列表全库无 school 过滤（已核验前两项）
- **位置**：`ExamService.java:52-54`（`findAllBySource`）；`StudentService.java:32-36`→`StudentRepository.search`；`DictionaryService.java:45-47/96-98/127-129`（`findAll`）。
- **现象**：任一登录老师都能看到/选到其他学校的数据（含学生姓名、学号、父母手机号等敏感字段），造成串数据与信息泄露。
- **建议**：所有读路径统一下推 `school_id`（`findBySchoolId(currentSchoolId)`）。

### M6/M7【严重 / P0】统计/排名对 SCOPE_ALL 跨校失真；缺 SCHOOL 级
- **位置**：`StatisticsService.courseStats:88-96`、`ComparisonService.comparison:84-87`、`TrendService.progress:63-66`、`RankingService.ranking:103-113`；底层 `GradeRepository.rankRows/stats/scores/courseRowsByExam` 均不带 `school_id`；`DataScopeService.visibleClassIds:39-43`（SCOPE_ALL→null=全局）。
- **现象**：SCOPE_ALL 用户看到的统计/排名/进步包含**全部学校**数据，结果严重失真且越权；当前只有 CLASS/ALL 两级，无法表达"仅看本校"。
- **建议**：所有统计查询下推 `school_id`；引入 `SCOPE_SCHOOL`；SCOPE_ALL/SCOPE_SCHOOL 一律叠加当前 `schoolId` 过滤。

### M4/M5【高 / P1】老师-班级归属、老师列表返回全库（PII 泄漏）
- **位置**：`TeacherClassController.java:23-28`→`TeacherClassService.query` 无参 `findAll`；`AuthController.java:74-78`→`accountRepository.findByRole(TEACHER)`，`toView` 暴露 `phone/schoolId`。
- **建议**：`findByRole` 改 `findByRoleAndSchoolId`；`toView` 收敛敏感字段。

### M8/M9【高 / P1】写路径信任客户端 schoolId；家长绑定可越校
- **位置**：`LevelService.create:29`、`DictionaryService.createClass:54-56`、`TeacherClassService.assign:54-57`（信任 `req.getSchoolId()`）；`ParentService.bind:67`/`claim:204`（`findByStudentNoAndNameAndDeletedFalse` 全局）。
- **建议**：写路径 `schoolId` 一律以登录上下文为准，禁止客户端覆盖；绑定范围限定为 `school_id=家长.schoolId` 的学生。

### E1/E2【高 / P1】ExamType 唯一性校验与复合唯一键矛盾
- **位置**：`ExamTypeRepository.java:8`（`existsByName` 全局）；实体键 `uk_exam_type_school_name(school_id,name)`；`DictionaryService.createExamType:131-138` 未 `setSchoolId`。
- **现象**：B 校创建"期中"因 A 校已存在被误报"已存在"→ 正常录入失败；且所有考试类型 `school_id` 恒 NULL，跨校无法独立管理。
- **建议**：`existsBySchoolIdAndName(schoolId,name)`；`createExamType` 写入当前 `schoolId` 并按其过滤。

### O1【高 / P1】排名 scope 未实现（已核验，见 F4/O1）
- **建议**：实现 scope 语义并按当前 school 约束。

### S2/S3【高 / P1】种子数据 school_id 不一致
- **位置**：`DataSeeder.java`（Level/Class 有 school；Course/ExamType/Exam/Student/Grade 全 NULL；种子 parent 无 phone）。
- **现象**：种子成绩 `school_id` 恒 NULL → 按校查询返回空；课程/考试类型/考试为 NULL 又进入每校列表造成冲突；种子家长无 phone 导致绑定/手机号登录演示链路起不来。
- **建议**：种子中对学生 `setSchoolId(school.getId())` 并回填关联；种子 parent 设与子女一致的 phone；用更稳健的幂等标识（S4）。

### E4【中 / P2】实体无 DB 外键 → 删除产生孤儿数据
- **位置**：全部实体（`Student.schoolId/classId`、`Exam.schoolId`、`Grade.*` 等）均用 `@Column` 普通 Long 列，无 `@ManyToOne/@JoinColumn`。
- **现象**：规范文档写"FK …"，实现无 DB 外键；删除学校/班级/学生/考试不触发级联也不报错 → 孤儿数据（如 `SchoolService.delete` 直接 `deleteById`）。
- **建议**：关键路径加 `@ManyToOne`+外键或显式依赖清理，删除前校验引用。

### F2【中 / P2】`system_setting` 无 school_id
- **位置**：`SystemSetting.java:13`（唯一键仅 `skey`）。
- **现象**：`parent_rank_visible/std_weight_mode` 等无法按校独立配置，多校相互干扰（规范注明 S2 决策）。
- **建议**：S2 落地的 `(school_id, skey)` 唯一键。

### 其他 P2 数据隐患
- **E3**：`ClassRepository.existsByName` 全局 vs 复合唯一键，正常带 schoolId 路径正确，缺失时退回全局校验。统一 `existsByNameAndSchoolId`。
- **F4**：布尔/整型默认值仅 Java 侧，prod `ddl-auto=validate` 下 DDL 基线需显式 `DEFAULT`（如 `Student.enrolled`、`Course.fullScore`、`Account.scopeType`）。
- **S4**：种子幂等闸仅看 `classRepository.count()>0`，部分表已存在时可能重复播种触发唯一约束异常。
- **S5**：种子家长无 phone → 绑定/手机号登录演示起不来。
- **O2**：任意 teacher 可建/删学校，删除无依赖清理（应仅超管）。
- **O3**：`Account.toView` 暴露 phone；`uk_account_phone` 允许多 null（可注册多个无 phone 家长，半成品路径）。
- **O4**：`ParentService.bind` 的 relation 接受非枚举"家长"字符串（`relation` 规范为 father/mother/other）。
- **O5**：`GradeService.toEntity` 在学生软删/无校时 grade.school_id 静默 NULL。

## 七、一致性改进总建议（架构级）

1. **建立中央数据范围切面（最高优先级）**：多租户"方案A"的 `school_id` 当前"写路径部分填充、读路径几乎完全不消费"，teacher 隔离仅靠 `teacher_class` 班级成员关系兜底，SCOPE_ALL/全部列表与统计直接跨校。建议在 **repository 层统一强制所有多租户表查询带 `school_id`**（引入 `@Where`/查询基类或 AOP 拦截），从架构上消除 M1–M7、E5 这类系统性泄漏，否则逐接口打补丁难以收敛。
2. **统一"生产"语义**：让启动器支持 `profile=` → 拼 `--spring.profiles.active=pg`，使 `ProductionGuard` 真正生效；`application-pg.yml` 显式 `app.seed.enabled:false` 与 PostgreSQL 凭据；README 文档化必设环境变量。
3. **补齐账号与权限模型**：新增 teacher 管理接口（强制 `schoolId`+`scopeType`），引入 `SCOPE_SCHOOL` 级；写路径 schoolId 一律取自登录上下文。
4. **前后端功能接线对齐**：拉通"已实现未上线"的孤儿（家长认领/自建、科目组合/总分），删除或接线二选一；统计各 Tab 状态独立、scope 真正生效；学生下拉分页。
5. **文档与代码对齐**：刷新 README（增启动器章节、端口口径、生产门禁清单、真实模块矩阵），删除 Pinia 虚列；统一 el-radio 取值风格。
6. **启动器小修**：顺延同步状态栏端口、初始化挂起 `chkAuto` 事件、健康检查特征不硬绑首页标题。
