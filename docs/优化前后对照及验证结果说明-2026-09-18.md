## 二、逐类问题定位、改进目标与落地优化

### 类别 A：来源字符串字面量散落（可维护性）

**具体表现**：`"teacher"` / `"parent"` / `"school"` 三个来源标记在 `GradeService`、`ParentService`、`DataSeeder`、`ExamService`、`StatisticsService` 等多处硬编码为字符串字面量。一旦拼写漂移（如 `"teahcer"`），会造成：
- 数据源判定逻辑静默失效（家长成绩被当老师成绩 / 反之）；
- 数据库 `source` 字段出现非法取值，口径被污染。

**改进目标**：来源值集中为编译期常量，杜绝拼写漂移；一处定义、全局引用。

**落地**：新增 `com.exam.common.GradeSources` 常量类：

```java
public final class GradeSources {
    private GradeSources() {}
    public static final String TEACHER = "teacher";
    public static final String PARENT = "parent";
    public static final String SCHOOL = "school";
}
```

并将 `GradeService`（约 8 处）、`ParentService`、`DataSeeder`、`ExamService`、`StatisticsService`（多处）的 `"teacher"/"parent"/"school"` 字面量全部替换为 `GradeSources.TEACHER/PARENT/SCHOOL`。

**对照**：改动前后逻辑等价（常量值与原字面量一致），仅提升可读性与抗漂移能力。

---

### 类别 B：JwtUtil 手工字符串解析（健壮性/安全）

**具体表现**：原 `JwtUtil.verify()` 用 `indexOf`/`substring` 手工定位 `uid/ver/exp/jti` 字段，靠固定分隔符与下标截取。JWT payload 结构或转义变化时易出现下标越界、截取错位，甚至解析绕过。

**改进目标**：用成熟的 JSON 解析器解析 payload，按字段名取值，杜绝手工下标依赖。

**落地**：`JwtUtil` 引入 `ObjectMapper`，`verify()` 改为 `OBJECT_MAPPER.readTree(payload)` 后按 `uid/ver/exp/jti` 节点取值；保留原有效期校验与 blank-jti 判空逻辑，行为不变。

**对照**：

| 项 | 优化前 | 优化后 |
|---|---|---|
| 解析方式 | `indexOf`+`substring` 手工截取 | `Jackson JsonNode.readTree` 字段取值 |
| 脆弱点 | 下标越界、格式漂移错位 | 结构合法即解析，非法返回拒绝 |
| 可维护性 | 依赖索引常量，改字段需数下标 | 按字段名，直观 |

---

### 类别 C：CORS/CSRF 白名单与有效期硬编码（可配置性）

**具体表现**：`AuthInterceptor` 中 `ALLOWED_ORIGINS` 与有效期 TTL 为 `static final` 硬编码；`CorsConfig` 同样硬编码来源数组。切换部署域名必须改源码重编。

**改进目标**：来源白名单外置为配置，生产按实际域名注入，去硬编码。

**落地**：
- `application.yml` / `application-prod.yml` 新增 `app.security.allowed-origins: ${APP_ALLOWED_ORIGINS:...}`（开发默认 `localhost:5173,127.0.0.1:5173`；生产默认空即拒绝跨源，避免默认值上线）。
- `AuthInterceptor` 与 `CorsConfig` 改由 `@Value("${app.security.allowed-origins:}")` 注入并拆分（逗号分隔、trim、空过滤）。

**对照**：部署端改环境变量即可调整白名单，无需改码；生产默认收紧为「空 = 仅同源」。

---

### 类别 D：前端 Pinia 死依赖（依赖治理）

**具体表现**：`package.json` 声明 `pinia` 且在 `main.js` 执行 `app.use(createPinia())`，但项目状态管理实际用轻量组合式/原生，Pinia 未被任何业务使用——属于死依赖，增打包体积与心智负担。

**改进目标**：移除未使用的运行时依赖。

**落地**：`frontend/package.json` 删除 `"pinia": "^2.1.7"`；`main.js` 删除 `createPinia` 引入与 `app.use(createPinia())`。

**验证**：`npm run build` exit 0（打包产物移除 Pinia 相关 chunk，体积下降）。

---

### 类别 E：StatisticsService「上帝类」（可维护性/可扩展性）

**具体表现**：`StatisticsService` 约 **931 行**，混合「查库 + 权限过滤 + 结果组装」与「纯数值计算（分布/聚合/名次/标准分/换算）」两种职责，职责不单一、难以单独单测、函数粒度过大。

**改进目标**：抽取**纯计算层** `StatMath`（无 IO、无权限、无登录上下文），`StatisticsService` 只保留查询与业务编排；计算逻辑可独立复用与单测；为后续按报表拆多个 Service 打底。

**落地**：
- 新增 `com.exam.service.StatMath`（`@Component`）：`item / isPass / isExcellent / referenceFull / distribution / aggregate / assignRank / weightedStdScore / parseStdWeights / percent / round1 / toBigDecimal / toLong`，及 `ScoreItem`/`StdItem` 两个 `public static` 值对象。
- 重写 `StatisticsService`：注入 `StatMath stat`，删除本地重复的辅助方法与内部类，相关调用改委托 `stat.*`；保留全部业务逻辑与统计口径不变（及格=满分60%、优秀=满分85%、分数段按得分率）。

**对照（规模）**：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| StatisticsService | 约 931 行（含计算+编排） | 约 700 行（纯编排） |
| StatMath | 不存在 | 新增纯计算组件（约 235 行） |
| 职责 | 混合 | 编排/计算分离 |
| 单测友好度 | 计算逻辑藏在私有方法，难直接测 | 纯函数可独立单测 |

> 说明：涉及 `StatisticsService` 的重写在写盘时曾因「文件被外部脚本修改」校验而失败一次，已通过对磁盘最新副本重新完整读取后重写解决；`SettingsService` 注入完整保留，无 NPE 风险（本次回归 62 项单测全绿佐证）。

---

### 类别 F：会话态内存化不可扩展（可扩展性/规模化）

**具体表现**：登出拉黑、token 版本、登录失败计数直接散置于 `AuthService` 的三个 `ConcurrentHashMap` 字段；单机可用，但规模化（多实例/Redis 集群）时无法共享，需改业务代码。

**改进目标**：将**会话撤销/锁定过程状态**抽象为接口，默认保留内存实现，同时具备 Redis 就绪的替换点。

**落地**：
- 新增 `com.exam.service.RevocationStore` 接口：`blacklist(jti,exp) / isBlacklisted / tokenVersion(accountId) / bumpTokenVersion / failureCount(key) / recordFailure / clearFailure`。
- 新增默认实现 `InMemoryRevocationStore`（`@Component`，`ConcurrentHashMap`；`recordFailure` 同步化；`blacklist` 顺带清理过期 jti）。
- `AuthService` 注入委托 `RevocationStore`，删除内部三个 `ConcurrentHashMap` 字段；登出拉黑、改密/重置密码 `bumpTokenVersion`、登录 `findByToken` 版本+拉黑校验、失败计数全部走接口。

**对照**：行为等价（62 项单测含 AuthFlow/LoginLock 全绿）；未来接 Redis 只需新增 `RedisRevocationStore` 实现并替换 bean，业务零改动。

## 六、遗留可选优化（需确认后开展）

评审报告指出、本轮回溯**未落地**的更大范围项，避免在未确认下引入风险：

1. **租户隔离「约定式 → 强约束」**：当前 `school_id` 为逻辑隔离（`Grade` 无 `school_id`，经 `student.school_id` 推导）。可选增强：
   - `grade` 等表冗余 `school_id` + 复合唯一键 `(school_id, student_id, exam_id, course_id, source)` + 索引；
   - Repository 层强制按 `school_id` 行级过滤（防未来遗漏过滤点）；
   - DB 外键/触发器等硬约束。
2. **前端测试增厚**：当前 12 项偏薄，建议覆盖统计组件交互、权限路由、异常/空态、ECharts 挂载等。

> 两项均属结构性改动，涉及 DDL 基线文档（`统一数据库字段规范-第六轮DDL基线.md`）同步与回归面扩大，建议先评审方案再落地。
