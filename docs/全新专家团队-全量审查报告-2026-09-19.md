## 二、已具备的正面防护（审查确认为正确，避免重复整改）

- **会话**：JWT 用 HMAC-SHA256 + `MessageDigest.isEqual` 常量时间验签（`JwtUtil:74-77`）；登出 jti 黑名单 + 改密/重置版本失效双通道集中失效；登录失败锁定键按 `accountId` 归一化（双通道不可绕过，`AuthService:77-105`）。
- **传输/凭证**：HttpOnly + SameSite=Lax Cookie（`AuthController:62-66`），前端 localStorage 不存 token；全局 `SecurityHeadersFilter` 统一附加 CSP/nosniff/X-Frame-Options/Referrer-Policy（覆盖放行路径）。
- **加密**：身份证 AES-GCM + 随机 12B IV + 认证标签（`AesCrypto`），密码 BCrypt；`PasswordHash` 加 `@JsonIgnore` 纵深防泄漏。
- **写路径入校**：create 侧 class/course/exam/examType/level 强制归属登录校、不信任请求体（B4）；学校 CRUD 限 SCOPE_ALL。
- **级联安全网**：删除父级（学校/级部/班级/课程/考试类型）前校验子级引用（B5）。
- **读路径班级域（多数）**：list/统计/排名主路径已做 CLSASS/SCHOOL/ALL 收敛或 school 下推。
- **启动器**：UTF-8 编解码防乱码、健康轮询 `Timeout=2000`+`Proxy=null`+首页特征校验防残留误判、退出 Kill 清理子进程、无明文凭据落盘。

## 四、误报 / 纠正（诚实标注，避免无效整改）

| 原论断 | 核验结论 |
|---|---|
| 前端"无 ADMIN 路由 → 死循环重定向"（前端专家 P1） | **误报**。`Account.java` 无 `ROLE_ADMIN`，`DataSeeder.java:232` 的 admin 实际 `role=TEACHER`+`SCOPE_ALL`，可正常进入教师路由。当前角色模型下不成立（仅当未来引入 ADMIN 角色才需补落地页） |

## 五、改进建议（按优先级落地）

**第一批（安全止血，P1）**
1. H2 console 默认关闭：`application.yml` 的 `spring.h2.console.enabled` 默认 `false`，仅开发 profile 开启；或对 `/h2-console` 增加鉴权。**（与默认单机部署直接相关，最优先）**
2. `ProductionGuard` 收紧：将门禁判定从"仅 prod/pg"改为"默认 JWT/AES 密钥即拒启"（即不以 profile 名称为唯一依据），杜绝默认密钥裸奔。
3. `StudentService.getById` 补入校校验：取学生后校验 `schoolId==登录校`（或 `canManageClass`）；CLASS 老师再校验班级可见。
4. `resetParentPassword` 补归属校验：仅允许重置"绑定了本校学生 / 同校 studentId 关联家长 且 调用者为本校或 SCOPE_ALL"；`defaultPassword` 改为后端由该生身份证后 8 位统一计算，不信任调用方传入值。
5. `StatQuerySupport.visibleGrades` 老师分支补 school 兜底：与 `schoolFilterForStatistics` 对齐，`studentId` 对应学生 schoolId 非登录校则拒（覆盖阶段 B 遗漏边角）。
6. `LevelService.update` / `DictionaryService.updateClass` 对齐 create 强制入校口径，并重校 `(school_id,name)` 唯一键与 level 归属同校。
7. `ExamService.getById` 对 school 来源考试补 `schoolId==登录校` 校验。

**第二批（一致性/健壮，P2）**
8. 统一成绩 tenant 过滤基准为 `s.school_id`（`search` 改 join Student），`grade.school_id` 仅作索引。
9. 修正 V2 SQL 死代码 step6 / 让 Java 迁移器也回填 grade，两套口径对齐。
10. 前端学生列表改分页/搜索，移除 `size:1000` 兜底；统一 grades 返回形态解析；修批量录入 checkbox。
11. 补 Cookie `Secure`（HTTPS 下）；`InMemoryRevocationStore` 在文档注明重启失效边界（多实例需换 Redis）。
12. 全量刷新契约文档（至少修正排名路径/参数、DataScope 注释、前端测试计数 73）。

**第三批（体验/纵深，P3）**：CSV 公式前缀；密码强度下限提升；localStorage 白名单缓存；启动器日志脱敏启动命令；重复查询合并。

## 六、结论

本次全新团队多视角审查共发现：**P1 高危 7 项、P2 中危 12 项、P3 低危 10 项，误报 2 处已纠正**。

最值得优先处置的是**安全止血类 P1**：#1 H2 console 无鉴权暴露、#2 生产门禁可被 profile 绕过、#4 密码重置越权接管、#3/#5/#6/#7 多租户越权读写。其中 #3/#5/#6/#7 与本项目刚落地的多租户隔离强约束目标直接相关，属于"读/写路径仍有漏校点"——建议在下一阶段专项收口，以配合 `docs/改造设计方案-多租户隔离-20260919.md` 的闭环目标。

文档不一致（#13 排名契约、#14 DataScope 注释）为明确的文档-代码漂移，建议随整改批量刷新。

> 说明：本报告基于静态代码审查 + 关键路径单测证据；运行期真实 HTTP 往返受沙箱网络代理限制，P1 越权类问题的最终以修复后回归测试 + 真实接口验证为准。
