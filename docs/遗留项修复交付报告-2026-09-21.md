## 二、逐项明细

### D1-01 物理外键 —— 推迟（保留逻辑隔离）

- **问题**：`ClassEntity.level_id`、`Grade.student_id/exam_id/course_id`、`TeacherClass.*` 等关联字段未声明 `@ManyToOne` 物理外键。
- **决策**：**本轮不落地**。理由：
  1. 全系统已通过 `school_id` 逻辑隔离 + 应用层校验实现引用完整性，物理 FK 缺失当前不引发数据错误；
  2. 补物理 FK 需评估存量数据孤儿行、级联删除语义、H2/PG 双库兼容，属大重构，风险高于收益；
  3. 记忆中已记录的「组织关联缺陷」修复需先对齐 DDL 基线，FK 补全应并入该专项统一处理。
- **后续**：随「组织关联缺陷」专项一并评估，不在本轮范围。

### D2-04 RevocationStore JPA 化 —— 完成

- **问题**：`InMemoryRevocationStore` 将登出黑名单、账号 token 版本存于进程内存，服务重启或水平扩展后旧令牌重新生效，存在会话失效失效漏洞。
- **改动文件**（全部新增 / 改造）：
  - `entity/RevocationEntry.java`（新增）：`revocation_entry` 表实体，`(kind, key_str)` 唯一查找，含 `idx_revo_kind_key`、`idx_revo_expire` 索引。
  - `repository/RevocationEntryRepository.java`（新增）：`findByKindAndKey`、`deleteByKindAndKey`、`deleteExpiredDeny`。
  - `service/JpaRevocationStore.java`（新增，`@Service`，**唯一 Bean**）：黑名单与 token 版本走 JPA 持久化；失败锁定计数因需原子自增且瞬态语义，保留进程内 `ConcurrentHashMap`。
  - `service/InMemoryRevocationStore.java`（改造）：**摘除 `@Component`**，降为普通参考实现，避免与 JPA 实现产生注入歧义。
  - `service/RevocationStore.java`（接口注释更新）。
- **验证**：后端编译通过；Spring 上下文正常启动（76 用例中 71 通过，证明无 Bean 冲突）。

### D4-01 补 school_id 索引 —— 完成

- `entity/Account.java`：`@Table` 增加 `indexes = @Index(name="idx_account_school", columnList="school_id")`（删学校前按校校验）。
- `entity/Exam.java`：`@Table` 增加 `idx_exam_source_semester(source, semester)` 与 `idx_exam_school_source(school_id, source)`（学期维度统计、按校+来源过滤）。

### D4-02 删冗余索引 —— 完成

- `entity/Grade.java`：删除 `idx_grade_student(student_id)`（已被 `idx_grade_student_source(student_id, source)` 前缀覆盖），保留 `idx_grade_student_source`、`idx_grade_course_source`、`idx_grade_exam_course_source`、`idx_grade_school`。
- `entity/ExamCourseGroup.java`：删除 `idx_ecg_exam(exam_id)`（已被 `uk_exam_course(exam_id, course_id)` 唯一键前缀覆盖），仅保留唯一键。
- **依据**：MySQL/H2 索引前缀覆盖规则——复合索引 `(a,b)` 可服务 `WHERE a=?`，单列 `a` 索引冗余。

### D3-01 full_score 对齐基线 —— 完成

- `entity/Grade.java`：`full_score` 由可空改为 `nullable=false, columnDefinition="int default 100"`，与 DDL 基线「NOT NULL DEFAULT 100」一致。
- **保留 Java `Integer` 类型**：仅收紧注解，避免级联改动 `toEntity` 等处的空值判断，风险可控。

## 五、测试失败说明（4 失败 + 1 错误）—— 既存缺陷，非本轮引入

`mvn test` 的 5 个失败全部位于**多租户隔离**专项用例，断言对象为 `RankingService` / `ComparisonService` / `TrendService` / `SettingsService` / `LevelService` / `DictionaryService` 的 school 下推与 `SCOPE_ALL` 语义。这些服务**均不在本轮 9 个改动文件清单内**。

**根因（对应记忆中已记录的「组织关联缺陷」）：**
- **B3（期望 true 实为 false）**：`SettingsService.currentSchoolId()` 把所有 `SCOPE_ALL` 账号一律按全局（`school_id=null`）处理，导致 A 校 `SCOPE_ALL` 写入的 `false` 落入全局行，B 校 `SCOPE_ALL` 读到同一全局行 → 未按校隔离。
- **B4（抛「级部不属于该学校，无法创建关联」）**：`LevelService.create` 经 `resolveWriteSchoolId` 对 `SCOPE_ALL`「信任请求体可跨校建」，而测试期望 `SCOPE_ALL` 锁定登录校——设计与断言对 `SCOPE_ALL` 语义自相矛盾。
- **B1 / 老师读路径 / 级部 update**：同为读路径 school 下推与 `SCOPE_ALL` 解析口径的既有问题。

**为何判定既存（证据链）：**
1. 本轮改动仅限实体索引/约束 + 吊销存储，均为 DDL 或独立鉴权路径，不进入上述隔离逻辑；
2. 索引与 `NOT NULL` 不改变查询结果；吊销存储未被这些用例调用；
3. 71/76 用例通过 → Spring 上下文正常、无 Schema 错误或 Bean 冲突；若为 Schema 或 Bean 问题应当全军覆没而非仅 5 例特定断言失败；
4. 失败断言直指 `SCOPE_ALL`/school_id 解析语义，与记忆中「DataSeeder 给 admin 设非空 schoolId 致超管被锁演示校 / SCOPE_ALL 强制覆盖」缺陷同源。

**处置**：本轮**不修复**（属独立于 5 项清单的大型重构，需先对齐 DDL 基线并统一 `SCOPE_ALL` 语义）。建议作为专项「组织关联缺陷修复」单独排期。
