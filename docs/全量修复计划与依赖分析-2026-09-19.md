# 全量审查问题 · 修复计划与依赖分析

> 版本：v1.0（2026-09-19）
> 依据：《全新专家团队-全量审查报告-2026-09-19》全部问题（P1×7、P2×12、P3×10，误报 2 处已排除）。
> 本计划先梳理各问题之间的**关联性/依赖/连锁影响**，再按**影响范围与风险程度**排序落地，最终全量回归并评审打分（目标 ≥4.8/5）。

## 一、依赖关系总览（谁影响谁）

```
                    ┌─────────────────────────────────────────────┐
  最高连锁 #8 成绩过滤基准  ──联动──► #9 V2 SQL 死代码/迁移器 grade 回填
   (g.school_id vs s.school_id)     （两套口径须对齐，否则放大 #8）
                    └───────────────┬─────────────────────────────┘
                                    │ 影响统计/排名/对比/进步全链路
                    ┌───────────────▼─────────────────────────────┐
   P1 越权组 #3/#5/#6/#7（学生/成绩/字典/考试归属校验）             │
     └─ 共享「登录校校验 + canManageClass」模式，彼此正交、独立     │
   #4 密码重置越权（API 交互，独立）                               │
   #2 生产门禁收紧（配置层，注意保留单机 H2 默认可用）              │
                    └──────────────────────────────────────────────┘

  一致性组：#10 CSRF Origin-null / #11 Cookie Secure / #12 内存失效
           （#12 为文档说明，无代码连锁）

  前端组：#13 契约文档 / #15 size:1000 / #16 返回形态 / #17 checkbox
          / #18 localStorage / #19 家长越权
          （纯前端，与后端契约 #13 耦合，须前后对齐）

  P3 纵深组：#20~#29（独立，互不阻塞）
```

**关键连锁项判定：**
- **#8 是唯一需要全链路回归的高连锁项**：它改变 `GradeRepository.search` 的 tenant 过滤基准（改用 `s.school_id`，join Student），直接影响老师成绩列表（`search`）与统计/排名（`stats/scores/rankRows/courseRowsByExam`）的数据集合一致性。必须与 **#9**（V2 SQL 死代码 step6、Java 迁移器补 grade）协同，否则两套口径继续打架。
- **#2 门禁收紧风险最高**：`ProductionGuard` 现行仅当激活 `prod/pg` profile 才拒启；若改为「默认密钥即拒启」，会误伤**默认单机 H2 部署**（启动器 + 默认 yml 场景本就无 profile、用默认密钥）。故 #2 采用**渐进收紧**：默认单机仍可启动（保留可用），但在非 prod 且使用默认密钥时输出**强烈告警日志**，并只在 `prod/pg` 下 fail-fast（现状保留）+ 增加「默认密钥+非本机」的告警，而非无条件拒启。这样既堵住"误认为安全"的心理，又不破坏既有默认部署。
- **P1 越权组彼此正交但共享校验工具**：均不互相影响，可并行；但每个改动后都需跑对应回归（尤其 #5 触及阶段 B 已落地的 `visibleGrades`，须保证 CLASS/SCHOOL/ALL 三档语义不回退）。

## 三、每个问题的落地要点（含连锁护栏）

### 批次 1（配置 + 文档）
- **#1 H2 console 默认关闭**：`application.yml` 的 `spring.h2.console.enabled` 由 `true` → `false`，并新增开发 profile 说明；prod/pg 本就 `false`（保持）。连锁护栏：默认单机部署需数据库管理但**不暴露 Web 控制台**，文件库读写不受影响（控制台仅 WEB UI）。→ 保留 `path` 配置，加注释指引用 IDE/DB 客户端直连。
- **#13 契约文档排名路径**：`个人版校园版-API契约与测试说明.md:88` 的 `/api/statistics/ranking` → `/api/statistics/rank`，参数对齐代码（`examId/courseId/classScope/showTies/scope`）。
- **#14 DataScopeService 注释**：`Grade 无 classId/schoolId 冗余字段` → 更新为「Grade 已有 `school_id` 冗余快照（阶段 B 增加），`class_id` 仍依赖 Student 推导」。
- **#12 InMemoryRevocationStore 边界**：在 `RevocationStore`/`InMemory` 注释与部署文档补充「重启即失效、多实例需 Redis」的明确边界（代码已有注释，落文档）。

### 批次 2（P1 安全止血）
- **#3 StudentService.getById 补入校校验**：取学生后校验 `schoolId` 归属（`currentSchoolId != null && !equals → 403`），CLASS 老师再校验 `canManageClass`；SCOPE_ALL/超管放开。连锁护栏：`update/delete` 已复用 `getById`，补校验后 update/delete 也自动获得归属保护（**本改造顺带加固 update/delete**，属正面连锁）。
- **#5 StatQuerySupport.visibleGrades 补 school 兜底**：老师分支在 `canManageClass` 前增加 `schoolId` 归属校验（与 `schoolFilterForStatistics` 对齐）；覆盖阶段 B 遗漏的「按 id 取再内存过滤」路径。连锁护栏：CLASS/SCHOOL/ALL 三档语义保持。
- **#6 LevelService.update / DictionaryService.updateClass 强制入校**：对齐 create 的 B4 口径（登录校优先），并重校 `(school_id,name)` 唯一键与 level 归属同校。
- **#7 ExamService**：school 来源考试的 `getById` 补 `schoolId==登录校` 校验；`saveCourseGroups` 的 `courseGroup.schoolId` 改为取 `e.getSchoolId()`（考试归属校）而非登录校。
- **#4 密码重置越权**：`AuthController.resetParentPassword` 仅 `requireRole(TEACHER)` → 增加「家长 schoolId==登录校 或 调用者为 SCOPE_ALL」校验；`defaultPassword` 不再信任调用方，由后端取该生身份证后 8 位（AES 解密）统一计算。连锁护栏：需 `ParentStudentBindRepository` 反查家长绑定学生；若家长未绑生或非同校则拒。**改造需新增依赖注入，注意不破坏既有测试签名。**
- **#2 ProductionGuard 渐进收紧**：非 prod/pg 且使用默认 JWT/AES 密钥时输出 `WARN` 告警日志（提示"默认密钥仅限本机演示，公网部署必须注入 APP_*"）；prod/pg 下 fail-fast 维持。连锁护栏：**保证默认单机启动器场景不阻塞**（否则破坏「启动器免装库一键启动」）。

### 批次 3（一致性 / 性能）
- **#8 成绩过滤基准统一**：`GradeRepository.search` 由 `g.schoolId = :schoolId` 改为 join Student、用 `s.schoolId = :schoolId`（与 stats/scores/rankRows/courseRowsByExam 一致）；`g.school_id` 仅作冗余索引/兜底。连锁护栏：`search` 现用于老师成绩列表（GradeService），须确认调用方传参不变；若自建生 student 缺失 `school_id`（null）在 `s.schoolId=:schoolId` 下会被排除——与既有行为（g.schoolId 兜底）需权衡，统一以「学生归属为准」为准（符合多租户语义）。
- **#9 V2 SQL 死代码 + 迁移器补 grade**：删除/修正 `V2__backfill_school_id.sql` 的 step6 死代码（step1 已全量置默认后 step6 的 NOT EXISTS 分支恒不成立）；`SchoolIdMigrationRunner.backfill` 增加 grade 回填（按学生 school_id，与 SQL 口径一致）。连锁护栏：与 #8 协同——grade 冗余快照仅作索引，权威归属以 student 为准。
- **#27 统计重复查询**：`StatisticsService.courseStats` 中 `stats(...).isEmpty() ? null : stats(...).get(0)` 触两次 SQL → 改先取 list 一次再判空取首。连锁护栏：纯性能，返回不变。
- **#28 排名 total 语义**：`RankingService` 家长档位 `total` 当前=RANGE 总人数（分母），与返回值说明易误读 → 增加 `rangeTotal` 字段并保留 `total`（说明语义），或明确文档标注。连锁护栏：前端需同步理解（纯新字段，向后兼容）。
- **#29 学期列表 school 过滤**：`ComparisonService.semesters()` 的 `findDistinctSemesters(SCHOOL)` 无校过滤 → 按登录校过滤（新增 repository 方法 或 过滤既有结果）。连锁护栏：低风险。
- **#10 CSRF Origin-null**：现 `Origin != null` 才校验 → 对非 GET 且 `Origin:null` 的请求，仅在"同源由 SameSite=Lax 兜底"前提下接受，做纵深加固但避免误伤（保持现状 + 注释说明，或对带凭据的跨站请求统一拒绝）。选定：**保持现状并补充注释**（SameSite=Lax 已挡主流浏览器，彻底拒绝 Origin-null 会误伤部分合法 CORS 场景）。
- **#11 Cookie Secure**：补充说明并支持 HTTPS 下由反向代理补加；不改代码（现状注释已说明），在部署文档强调 HTTPS 前提。

### 批次 4（P3 体验/纵深）
- **#20 密码强度下限**：注册/改密/重置的最小长度由 6 → 8（对齐身份证后 8 位语义），并提示复杂度。连锁护栏：**需同步审计现有测试**（LoginLockTest/AuthFlowTest 可能用 6 位密码，需改测试或保持 6 位+提示）。→ 若测试耦合深，降级为「保留 6 位下限 + 弱口令提示」，避免改崩测试。
- **#21 AesCrypto 短密钥填充弱化**：`padKey` 对非 16/24/32 长度 0 填充至 32 弱化 → 改为对非法长度抛异常（仅接受 16/24/32），或至少对过短密钥拒启。连锁护栏：`APP_CRYPTO_KEY` 长度不合法时应用启动失败属正确行为（安全优先）。
- **#22 CSV 公式注入**：`GradeQuery.vue` 导出对 `= + - @` 开头字段加 `'` 前缀。纯前端。
- **#23 ParentTrend 偏好保存脆弱**：`@change` 传值被忽略 → 改为显式读取 v-model 状态提交。
- **#24 localStorage 白名单**：`useAuth.setSession` 仅缓存 `{id,role,nickname,...}` 白名单字段，丢弃 phone/idCard 等敏感字段。
- **#25 启动器日志脱敏**：`ServerLauncher.cs` 启动命令日志对 `jvmOpts` 中疑似密钥/口令部分打码。
- **#26 启动器拼接转义**：注释说明本机 ini 写权限边界 + 加安全提示（保持简单，不引入复杂解析）。
