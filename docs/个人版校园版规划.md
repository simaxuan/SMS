# 考试成绩管理系统 · 个人版 / 校园版架构规划

> 文档性质：**架构规划（已实现 + 规划 双态）**。基础版（账号/角色/成绩来源隔离/个人版）已落地；第六轮 v5 已定稿并将新增多租户组织建模、统计三口径、加密与隐私等能力（见各节「状态」标注）。本文与《第六轮优化整改方案设计（v5 定稿）》及《统一数据库字段规范-第六轮DDL基线》对齐。
> 适用版本：在现有「成绩录入 / 成绩统计 / 满分可配置 / 得分率统计 / 个人版-校园版」基础上规划与演进。

---

## 1. 背景与目标

当前系统为单一角色、全员可见的「学校管理端」雏形。随着使用范围扩大，需要拆分为两种使用形态：

| 形态 | 定位 | 使用人 | 核心能力 |
| ---- | ---- | ------ | -------- |
| **校园版（学校端）** | 学校/班级整体管理 | 老师/教务 | 管理所有班级与学生；录入、查看**全部**学生成绩；查看全部统计 |
| **个人版（家长端）** | 面向单个家庭 | 家长 | 绑定**单个或多个**学生；**查看并录入**成绩；查看所绑定学生的统计 |

两个版本**共享同一套数据模型与业务规则**，通过「账号体系 + 角色 + 数据范围 + 成绩来源标识」实现隔离与权限控制。

---

## 2. 用户确认的关键规则（本规划的硬约束）

1. **个人版不仅可查看，还可录入成绩**（家长可以为自己绑定的孩子补录成绩）。
2. **老师录入的成绩，个人版（家长）不可修改、不可删除**（只读）。
3. **老师端无须查看个人版录入的成绩**（校园版看不到家长补录的数据）。
4. **老师端统计不要统计个人版录入的成绩**（统计口径仅基于老师录入的数据）。

> 一句话概括隔离：**成绩有两个"来源"，校园版只认"老师来源"，个人版"可看老师来源+自己录入的来源、只能改自己的来源"。**

## 3. 核心设计

### 3.1 账号与角色模型

新增基础账号体系（**已实现**：账号/角色/登录/鉴权）：

```
account（账号）
  id, username, password_hash, role, nickname, created_at
  -- v5 新增：phone(唯一, 家长登录名), school_id, scope_type(CLASS默认/ALL),
  --          wechat_openid, wechat_unionid, auth_type(password/wechat/phone),
  --          last_password_change

role ∈ { ADMIN, TEACHER, PARENT }
```

| 角色 | 数据范围 | 操作能力 |
| ---- | -------- | -------- |
| TEACHER / ADMIN | 全校（按班级/级部可再细分） | 读写全部成绩、删改、统计 |
| PARENT | 仅绑定的学生 | 读老师成绩 + 读写**自己录入**的成绩 |

> **v5 已定稿（规划态→待开发）**：`account` 扩展手机号、所属校 `school_id`、`scope_type`（CLASS 默认/ALL 三级范围）、微信预留字段（`wechat_openid/unionid/auth_type`）、`last_password_change` 审计；登录改为「学生姓名+手机号+密码」+失败锁定固定 5 次/15 分钟；微信登录仅 `POST /api/auth/wechat` 占位（本期不做）。

### 3.2 学生-家长绑定关系

```
parent_student_bind
  id, parent_account_id, student_id, relation(father/mother/other), created_at
  unique(parent_account_id, student_id)
```

- 一个家长可绑定**多个**学生；一个学生可被**多个**家长绑定（双父母各一账号，信息/编辑一致）。
- 家长只能访问 `parent_student_bind` 中关联到的学生。
- **v5 已定稿（规划态→待开发）**：绑定升级为**四要素**校验——学号 + 姓名 + 手机号 + 身份证后 8 位（hash 比对）+ 设置默认密码；默认密码 = 身份证后 8 位（BCrypt），**不强制首改**；恢复默认密码仅由老师端操作（审计留痕）；`student` 新增 `id_card(AES)`/`id_card_hash`/`father_phone`/`mother_phone`/`origin`/`parent_owner_account_id`/`enrolled`/`merged`/`school_id`。

### 3.3 成绩来源标识（隔离的关键）

在现有 `grade` 表新增字段：

```
grade.source   -- 'teacher' | 'parent'         成绩来源标识（默认 'teacher'）
grade.creator_account_id   -- 录入人账号（家长来源必填；老师来源可空=系统）
```

**权限/可见性规则（后端强制，前端隐藏）**：

| 场景 | 老师/校园版 | 家长/个人版 |
| ---- | ----------- | ----------- |
| 可见成绩 | 仅 `source='teacher'` | `source='teacher'`（只读）+ 自己 `source='parent'` |
| 录入 | 全校 | 仅绑定学生，`source='parent'` |
| 修改/删除 | 全部 `teacher` 来源 | **仅**自己录入的 `parent` 来源；**老师来源一律只读** |
| 统计 | **仅** `source='teacher'` | 绑定学生全部可见来源（老师+本人家长），但**老师端看不到、不算家长数据** |

> 这就是规则 2/3/4 的实现落点：老师端所有查询、统计接口统一加 `source='teacher'` 过滤；家长端写操作强制 `source='parent'` 且只能作用于自己录入的记录。

### 3.4 组织模型（校园版范围，v5 已定稿多租户）

**已实现**：`class_entity`（id/name/createdAt）。**v5 新增（规划态→待开发）**：独立 `school` / `level` 表 + `teacher_class` 归属表，class 挂级部与校园：

```
school（校园，多租户根）        id, name, code(UNIQUE)
level（级部/年级）             id, school_id, name           -- (school_id,name) 唯一
class_entity（班级）           id, name, level_id, school_id, created_at
teacher_class（老师-班级）     id, teacher_account_id, class_id  -- (teacher,class) 唯一
exam_course_group（考试-科目组合） id, exam_id, course_id, active, school_id(建议)
```

- `school → level → class → student` 四级归属；核心表带 `school_id` 实现多租户隔离（**方案 A**：`account/student/exam/course/exam_type` 显式带 `school_id`，`grade/class/teacher_class/bind` 经上层推导）。
- `account.scope_type`（CLASS 默认 / ALL）；`DataScopeService` 提供 `visibleClassIds/visibleLevelIds/schoolId`，支持 **class / level / school 三级范围**排名与统计。
- 本期若不做复杂权限，可先 `TEACHER` 默认全校读写，后续再加 `class_scope` 细分（v5 已将此升级为 teacher_class 归属 + 三级范围）。

#### 3.4.1 家长排名隐私（v5 已定稿）

新增 `parent_rank_detail`（默认 `aggregate`）：家长仅看本人 `{rank,score,percent,className,total}` + 班级/级部聚合，**不再返回全班明细**；另有 `limited` / `full`（仅 ALL 角色）档位。

## 5. 前端改动概览

| 端 | 改动 |
| ---- | ---- |
| 登录/注册 | 登录页；家长注册入口 |
| 应用入口 | 登录后按角色路由：校园版控制台 / 个人版控制台 |
| 学生选择 | 个人版学生选择器仅列绑定学生 |
| 录入/编辑 | 个人版录入即 `source=parent`；老师来源的单元格不可编辑（只读态） |
| 统计 | 个人版展示绑定学生视角；老师端保持全校（仅 teacher 来源） |

两种形态可**共用一套前端**（路由+角色判断），也可拆为两个独立部署（多租户）。建议首期共用一套、按账号角色显示不同界面。

---

## 6. 数据隔离与安全要点

1. **后端必须强制数据范围**，不得只靠前端隐藏按钮——防止越权访问他人/他班数据。
2. 家长接口一律按 `current_account → parent_student_bind → studentId` 推导数据范围，禁止前端传任意 studentId。
3. 统计、导出接口同样走 `DataScopeService`，杜绝"绕过列表直接调统计接口"。
4. 密码哈希存储（BCrypt），默认关闭调试账号。
