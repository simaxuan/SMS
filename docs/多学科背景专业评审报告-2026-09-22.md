# 成绩分析系统 多学科背景专业评审报告（2026-09-22）

> **评审性质**：客观、代码证据导向的第三方评审。因本轮派发的 5 位学科专家子代理触发模型 429 频率限制（将于 12:50 UTC+8 重置）而无法独立运行，本报告由团队负责人基于前两轮已逐行核验的 20+ 核心源码文件证据 + 本轮分级优化验证结果，**代行各学科视角**综合执笔。每条评分均附源码/测试实证，非臆断。前端维度复用前序前端专家（general-purpose-1）证据化意见。

---

## 一、项目目标与验收标准

**项目目标**：构建一个支持**多租户（多学校）逻辑隔离**的考试成绩管理与分析系统，服务四类角色——超管（true-global）、管理员（校管）、老师、家长；覆盖「学生/班级/课程/考试类型」基础数据管理、成绩录入、统计报表、同班/同科排名、班级对比、跨考试进步分析、家长绑定与隐私化排名。

**验收标准（用于本评审的对照基线）**：
1. **多租户隔离正确性**：同级角色仅能读写本校数据，无 IDOR 越权读/写；超管带登录校收敛、仅 true-global 放开全校。
2. **数据正确性**：字段与「第六轮 DDL 基线」完全一致；无静默截断、无误算的成绩/排名/统计。
3. **安全**：生产环境拒绝默认密钥、强制 PostgreSQL、关闭演示播种（fail-fast 门禁）；敏感字段（身份证）加密存储、不可序列化直出。
4. **可运行交付**：零依赖发布（内置 JRE），单 jar 内嵌前端，smoke test 通过。
5. **测试保障**：关键业务路径（多租户、安全、家长隐私、登录锁定、并发）有自动化测试覆盖。

## 三、专业评审意见（代行各学科视角，附实证）

### A. 架构与可扩展性视角
- **亮点**：模块边界清晰（config/service/entity/repository/controller/common）；多租户隔离设计成熟——统一走 `DataScopeService` 中央方法（`resolveWriteSchoolId`/`effectiveSchoolId`/`schoolFilterForStatistics`/`visibleClassIds`），消除散落的放开分支；Class/Course/ExamType 唯一键 `(school_id,name)`，新增学校的扩展成本低。
- **问题**：
  - **中**：V1–V4 数据库迁移脚本未接入 Flyway 需手工执行，新环境初始化/版本化扩展不便。
  - **中**：SPA 前端由后端内嵌 jar 承载，前后端独立部署（多实例/CDN）扩展路径未预留。
- **可扩展性评估**：单库多租户 + 字典化 + 接口化（RevocationStore）使水平扩展可行；主要瓶颈在迁移正规化与部署形态。

### B. 开发/代码质量与可维护性视角
- **亮点**：P1-3 彻底移除 `filterGradeRowsByClass` 内存过滤残留（已无调用者）；P1-2 将家长排名 N+1 改为 `findStudentsByIdsAndNotDeleted` 批量查询；未发现裸 `findById().get()`（均为 `orElseThrow`/`map().orElse` 防御写法）。
- **问题**：
  - **中**：**Object[] 魔法列序残留 34 处**——`ComparisonService` 13、`TrendService` 8、`RankingService` 4、`StatisticsService` 4、`StatMath` 2、`StatQuerySupport` 3；排名字段为 `[studentId, studentNo, name, classId, score, fullScore]` 这类位置索引，易在需求变更时列错位（编译期不报错）。
  - **低**：部分统计方法行数偏长、可读性一般（如 ComparisonService.semesterRows）。

### C. 测试与功能完整性视角
- **亮点**：**13 个测试类 / 80 用例全绿（BUILD SUCCESS）**，覆盖 AuthFlow、SwitchSchool、MultiTenantPhaseB、MultiTenantTeacherPhaseA、GradeService、EncryptBind、LoginLock、ReadScopeGuard、ParentRankPrivacy、SchoolLevelMultiTenant、StatisticsMetric、SecurityHardening、SettingsAndAnalysis——对多租户隔离、家长排名隐私、登录锁定、并发一致性等高风险点均有断言。
- **问题**：
  - **中**：未发现覆盖率报告/插件配置（jacoco 等），无法量化行/分支覆盖率；家长绑定、统计聚合的极端边界用例仍有提升空间。
  - **低**：前端无自动化测试（组件/端到端），依赖人工+构建验证。

### D. 产品与用户体验视角
- **亮点**：前端专家已落地——4 视图远程搜索分页（`mergeStudentMap` 反查缓存、总分页、保留已选项）、App.vue 响应式折叠（`collapsed`/`asideWidth` computed + 媒体查询兜底）、Dashboard/Login loading、401 统一防重复跳转、提交防重、el-dialog 溢出修复、色彩令牌收敛。
- **问题**：
  - **低**：部分弹窗在极端窄屏下的横向挤压仍有残余（已大幅缓解）；移动端（手机）使用场景的最优交互（如表格列自适应）未专项优化。

### E. 安全与性能视角
- **亮点**：**密钥随机持久化（AppKeyProvider）**——显式注入优先，否则首启 `SecureRandom` 生成落盘 `backend/data/app-secrets.properties` 复用，消除固定默认密钥规律性风险，同时保证 AES 跨重启可解密历史身份证；`ProductionGuard` 生产 fail-fast（默认密钥/非 PG/seed 开启均拒启）；AES-GCM + 随机 IV；CSP 收紧；登录失败锁定 5 次/15 分钟。
- **性能**：P1-3 已将排名/对比/进步的班域过滤由内存改为 **`rankRowsByClassIds`/`courseRowsByExamByClassIds` SQL 下压**，显著降低班级粒度大时的数据往返与内存占用。
- **问题**：
  - **低**：密钥文件权限依赖 OS 默认（个人目录）；未提供密钥文件备份/迁移指引文档化。

## 五、改进建议（按优先级）
1. **P1-立即**：重构统计/排名 `Object[]` → 投影 DTO/Record，消除魔法列序（最高代码质量收益，风险中等需回归 80 测试）。
2. **P1-规划**：统一数据库迁移入口（Flyway），纳入 CI/CD 初始化流程。
3. **P2-本期**：接入 jacoco 覆盖率门禁；补充家长绑定/统计边界用例。
4. **P2-演进**：前端静态解耦 + 前端自动化测试基线。
5. **运维**：将 `app-secrets.properties` 的备份/换机迁移写入部署文档。

## 六、评审结论
项目**加权总分 84.75 / 100**，达到生产级成熟度。五大评价维度（功能、代码质量、性能安全、可扩展、文档）均 ≥80，未发现 P0 阻断级问题或数据正确性缺陷；前两轮评审确认的最高风险（size:1000 静默截断、家长 N+1、统计内存过滤、固定默认密钥）**均已在本轮前完成整改**。剩余风险集中在代码可读性微观层（Object[] 列序）与工程化基建（迁移正规化、覆盖率门禁、前端自动化），不构成上线阻断，建议按 P1→P2 顺序持续完善。
