## 二、优化 1：ElementPlus / ECharts 按需引入

### 2.1 改动清单

**ElementPlus 按需（unplugin）**
- `frontend/package.json`：新增 devDependencies `unplugin-auto-import`、`unplugin-vue-components`。
- `frontend/vite.config.js`：接入 `AutoImport({ resolvers:[ElementPlusResolver()] })` + `Components({ resolvers:[ElementPlusResolver()] })`，组件、API 方法（ElMessage/ElMessageBox…）按需自动注入并携带样式。
- `frontend/src/main.js`：**移除** `app.use(ElementPlus)` 全量注册、`element-plus/dist/index.css` 全量样式与全局 280+ 图标批量注册。
- `frontend/src/App.vue`：改用 `el-config-provider :locale="zhCn"` 维持中文 locale；侧边菜单图标改为显式 `import { Odometer, User, … }` 按需引入。
- **移除 11 处 `import { ElMessage, ElMessageBox } from 'element-plus'` 根导出导入**（根导出不可摇树，会把整个 ElementPlus 拉入包），统一交给 unplugin-auto-import 从 `element-plus/es` 注入。

**ECharts 按需（echarts/core）**
- 新增 `frontend/src/utils/echarts.js`：用 `echarts/core` + `echarts/charts`（Bar/Pie/Line）+ `echarts/components`（Grid/Tooltip/Legend/Title）+ `echarts/renderers`（Canvas）按需 `use([...])`，默认导出配置好的 echarts。
- `Statistics.vue` / `StudentTrend.vue` / `parent/ParentTrend.vue`：由 `import * as echarts from 'echarts'` 改为引用共享按需模块 `../utils/echarts`。

### 2.2 体积实证（fe_build_rd5c.log，vite build 成功）

| 分包 | 第四轮全量引入 | 第五轮按需引入 | 降幅 |
|---|---|---|---|
| `vendor-echarts` | 822KB（gzip 270KB） | **362KB（gzip 123KB）** | **约 -56%** |
| `vendor-element` | 962KB（gzip 295KB） | **818KB（gzip 258KB）** | 约 -15%，且 CSS 已按需（229KB/组件级，不再全量 280KB） |
| 主包 `index.js` | 12.33KB | 12.47KB | 持平（业务代码） |

- 通过产物反查确认摇树生效：`ElCarousel/ElCollapse/ElBacktop/ElDescriptions/ElTree` 等未用组件已不在包内；src 中已无任何 `from 'element-plus'` / `from 'echarts'` 根路径导入。
- 说明：ElementPlus 因本应用 13 个页面确实重度使用 table/form/date-picker/select 等重型组件，其按需 JS 地板较高（818KB 为该真实使用集），主要收益落在 **ECharts 大幅瘦身 + ElementPlus 样式按需 + 移除全量注册与脆弱根导入**。

## 三、优化 2：studentTrend 批量加载（消除 N+1）

- `backend/src/main/java/com/exam/service/StatisticsService.java` `studentTrend(Long)`：
  - 原实现：外层遍历考试 `examRepository.findById(examId)`，内层每科 `courseRepository.findById(courseId)` —— 逐条 N+1。
  - 现实现：先收集去重 `examIds`/`courseIds`，`examRepository.findAllById(...)` / `courseRepository.findAllById(...)` 一次构建 `Map`，循环中 `O(1)` 取值。新增 `Set/HashSet` 导入。

### 协调修复清单（已落地并回归验证）

**后端**
1. **[P1] 家长「全校排名」名次**（StatisticsService.ranking）：`classScope=false` 分支改为先在完整 `ranked` 上 `assignRank`，再过滤绑定学生展示，杜绝单子女家长恒 rank=1。班级范围保持原重算逻辑。
2. **[P2] 学期对比取「最新成绩」**（semesterRows）：用「当前迭代下标」精确记录 examDate 最大行，替代原先 `rowIndex.get(sid)`（examId 顺序≠日期顺序时会取错）。
3. **[P2] 及格/优秀魔法数**：两处 `percent >= 60/85` 改为引用 `PASS_RATE_LINE/EXCELLENT_RATE_LINE * 100` 常量。
4. **[P2] 成绩并发唯一冲突**（GradeService.create 与 batchCreate）：`save` 捕获 `DataIntegrityViolationException` → 单条转 409 友好提示 / 批量静默跳过，消除并发重复录入返 500。
5. **[P2] H2 控制台**：生产 `application-pg.yml` 显式 `spring.h2.console.enabled:false`（base 演示保留）。
6. **[P2] ParentService.listBinds N+1**：绑定学生与其班级一次 `findAllById` 批量加载。
7. **[数据库 P1] exam 全表扫描**：`progress` 仅加载过滤后涉及考试的 examDate；`semesterRows` 改用 `findAllById(examIds)`（不再 `findAll()` 全表）。
8. **[产品 P1] 考试属主校验**（ExamService）：`getById` 对 `custom` 小测仅创建者可见（修 P2-12 信息泄露）；`update/delete` 复用该校验，使老师无法改删家长自定义小测（修 P1-2 跨属主写）。
9. **新增回归测试 2 项**（SettingsAndAnalysisTest）：「家长全校排名名次与教师端一致（P1）」「老师可查看学生个人趋势（studentTrend）」。

**前端**
10. **[P0-1] useAuth 会话同步**：新增 `setSession(session)` 更新共享 `auth` ref 并写 localStorage；`Login.vue` 登录成功改调 `setSession`，修登录后菜单/昵称/角色标签错乱；`logout` 统一走 `setSession(null)`。
11. **[P0-2] 补齐 missing API**：`examApi` 增加 `customCreate`（`POST /exams/custom`）、`customList`（`GET /exams/custom`），修家长录入小测不可用。
12. **[P1] 隐藏 Tab 图表空白**：Statistics.vue `el-tabs @tab-change="onTabChange"`，切换后 `nextTick` 重置三张图表尺寸。
13. **[P1] 登出不跳转**：App.vue 退出按钮 `@click="logout"` → `@click="handleLogout"`（含跳转登录页）。

### 遗留（产品/投入取舍项，已记录不做强行改动）
- **P2 家长「班内排名」返回全班明细**：与《统计维度差异分析》第 5.4「默认不显示绝对名次」存在张力；当前学校规模与权限矩阵以「个人版/小型校园版」定位，保留为显式可开关能力。如上线多租户校园版应默认收紧。
- **P1 教师=全校范围（无「我的班级」边界）**：当前明确为「教师=全校管理员」单人/管理员模式；真校园版需引入 teacher→class 归属并全链注入范围过滤。
- **P1 家长绑定仅凭「学号+姓名」无身份核验**：个人版可接受；校园版建议增加手机号/邀请码核验与失败响应统一。
- **P2 趋势「总分=原始分累加」跨满分不可比**：建议改「总得分率/标准分」口径（已列入技术债）。
- **文档口径过时**（一期规格 FR-104/FR-105 绝对分、唯一约束不含 source）：建议将一期规格升级为「口径基线」。
