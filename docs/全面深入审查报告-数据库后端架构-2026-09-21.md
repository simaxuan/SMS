## 一、审查方法说明

- **数据库专家**：逐文件实读 14 实体 + 14 Repository，对照《统一数据库字段规范-第六轮DDL基线》，覆盖实体关联、库表字段、索引设计三个维度。
- **后端专家**：逐文件实读 17 个 Service + 控制层，覆盖业务逻辑、并发一致性、备注文档维度。
- **架构专家**：在前两者基础上实读源码交叉印证，重点核实删除级联调用链、多租户口径一致性、索引与过滤匹配，并输出跨维度整体优先级。

三方结论互相印证，最终报告按 5 个维度组织，每一问题给出【级别】【位置】【描述】【建议】。

## 维度一 · 实体间关联关系

### 【高】D1-01 全部外键为裸 Long 字段，数据库无 FK 约束与级联
- **位置**：所有实体（典型：`Student.java:40`、`Grade.java:27/34/37`、`Exam.java:21`、`ClassEntity.java:27/31`、`TeacherClass.java:22/25`、`ParentStudentBind.java:19/22`）
- **描述**：关系全部以 `@Column Long xxxId` 建模，未用 `@ManyToOne/@JoinColumn(foreignKey=...)`，Hibernate 不生成 DB 外键，引用完整性 100% 依赖应用层。任一删除路径漏清理即产生孤儿数据，DB 层无法拦截。
- **建议**：核心父子关系补 DB 外键（`grade.student_id/exam_id/course_id`、`class.level_id/school_id` 等加 `@JoinColumn(foreignKey=@ForeignKey)` 或手写 `ALTER TABLE ADD CONSTRAINT ... FOREIGN KEY`）；若坚持应用级守护，须在建档文档写明"禁止物理删除父表，统一软删/守卫"硬规则，并补齐下述删除清理。

### 【高】D1-02 删除安全网缺口致孤儿数据（4 处，1 处潜伏）
经架构专家实读调用链，把"三处缺口"细化为四类，其中三处当前可达：
- **(a) Student→ParentStudentBind**：`StudentService.java:85-96` 软删学生，未清理绑定；`ParentStudentBindRepository` 无 `deleteByStudentId` 且无 student_id 单列索引。**当前可达孤儿**。
- **(b) Exam→ExamCourseGroup**：`ExamService.java:129-135` 删考试只拦 `gradeRepository.existsByExamId`，未检查/清理 `exam_course_group`（以裸 exam_id 引用）。学校级 `existsBySchoolId` 拦截了"该校有 ECG"，但**单考试粒度完全无防护**。**当前可达孤儿**。
- **(c) School→SystemSetting**：`SchoolService.java:102-114` `assertNoDependencies` 未检查 `systemSettingRepository`（且未注入），也未拦 `teacher_class`（后者被 `classRepository.existsBySchoolId` 传递覆盖、风险低）。删校后该校 `system_setting` 配置行成孤儿。**当前可达孤儿**。
- **(d) Account→ParentPreference/ParentStudentBind（潜伏）**：当前**无删除账号入口**（无 `deleteAccount/deleteParent` 方法），但 `ParentPreferenceRepository` 无 `deleteByAccountId`、`ParentStudentBindRepository` 无 `deleteByParentAccountId`——**连清理能力都缺失**，一旦上线账号删除必爆。
- **建议**：① 补 `ParentStudentBindRepository.deleteByStudentId` + `idx_psb_student(student_id)` 索引，软删学生时调用；② `ExamService.delete` 增加 `courseGroupRepository.existsByExamId` 拦截或先删 ECG；③ `SchoolService.assertNoDependencies` 补 `systemSettingRepository.existsBySchoolId`；④ 新增家长删除功能前预置 `deleteByParentAccountId`/`deleteByAccountId`。可仿照 `DictionaryService.deleteClass`（先清 teacher_class）的"级联清理典范"。

### 【中】D1-03 class.school_id 与 level.school_id 无一致性校验（跨租户风险）
- **位置**：`ClassEntity.java:27/31`、`Level.java:21`
- **描述**：class 同时存 `level_id` 与 `school_id`，可空且可指向不同学校（A 校 level + B 校 school），按校过滤出现跨租户错乱。
- **建议**：写路径由 `level_id` 推导回填 `class.schoolId = level.schoolId`，或应用校验 `level.schoolId == class.schoolId`；长期加 FK `class(level_id)→level(id)`。

### 【中】D1-04 跨实体 FK 一致性无校验（跨校组合脏数据）
- **位置**：`Exam.java:21`(exam_type_id)、`Grade.java:34/37`、`ExamCourseGroup.java:22/25`
- **描述**：`exam.exam_type_id` 与 `exam_type.school_id`、`grade.course_id` 与 `course.school_id`、组合表 exam/course 均可能引用他校记录，无应用/DB 校验，形成"某校考试挂他校科目"。
- **建议**：写路径校验外键对象与本校归属一致（如 `examType.schoolId == exam.schoolId`），或加冗余列+校验；FK 只能保证引用存在、不能保证两校一致。

## 维度二 · 业务逻辑关系

### 【高】D2-01 5 处读路径仍用 `user.getSchoolId()` 判归属，超管被误锁演示学校
- **位置**：
  - `StudentService.java:36`（`list`：`search(user.getSchoolId(),...)`）
  - `StudentService.java:45`（`getById` 跨校 403；被 update/delete 复用，写路径也中招）
  - `StudentService.java:113-114`（`apply`：`s.setSchoolId(user.getSchoolId())` 超管建学生错挂演示校）
  - `StatQuerySupport.java:62`（`visibleGrades` 跨校 403）
  - `ExamService.java:99`（`getById` 跨校 404）
  - `ComparisonService.java:125`（`semesters`：`findDistinctSemestersBySchool(..., user.getSchoolId())`）
- **描述**：`DataSeeder` 把种子 admin 设为 `SCOPE_ALL` 且 `schoolId=演示学校(非空)`。上述读路径以 `user.getSchoolId()!=null` 作为"按校下推/跨校拒权"判定，未加 `isGlobalAdmin()` 守卫 → 全局超管查学生/学期/成绩/考试详情被锁演示校。这与 `GradeService.list`、`RankingService`、`DictionaryService`、`SettingsService` 已正确用 `isGlobalAdmin()`/`schoolFilterForStatistics` **自相矛盾**。
- **建议**：统一改为 `dataScopeService.isGlobalAdmin() ? null : user.getSchoolId()`，或复用 `schoolFilterForStatistics(user)`。建议在 `DataScopeService` 增设单一权威方法（如 `effectiveSchoolId()`：超管返回 null、普通返登录校；`isCrossSchoolBlocked(user,target)`），5 处与后续所有"按校下推"统一引用，杜绝判据复制。

### 【中】D2-02 Grade 无乐观锁，并发更新"最后写入胜出"
- **位置**：`Grade.java:21-57`（无 `@Version`）、`GradeService.java:112-141`（update 先 findById 再 save）
- **描述**：两个并发更新同一成绩行互相覆盖，不抛 `OptimisticLockException`；唯一约束只防重复创建、不防并发修改。
- **建议**：`Grade` 实体加 `@Version Long version`；或 `update` 的 save 包 `try/catch(DataIntegrityViolationException)` 转 409。

### 【中】D2-03 唯一约束异常兜底不一致
- **位置**：`GradeService.java:140`（update 的 save 未捕获）、`ParentService.java:174`（`"SELF"+currentTimeMillis()` 自建学生学号并发同毫秒撞唯一键）
- **描述**：`create`(104)/`batchCreate`(177) 已捕获 `DataIntegrityViolationException` 转 409，但 `update`(140) 未捕获（改挂学生撞已有键→500）；自建学生 `studentNo` 同毫秒并发生成必撞 `uk_student_no`→未捕获→500。
- **建议**：① `update` 的 save 同样转 409；② 自建学号改用含账号ID+随机后缀/UUID 的生成，并对 save 捕获唯一约束异常转 409。

### 【中】D2-04 RevocationStore 内存实现：集群不共享 + 计数无原子同步
- **位置**：`AuthService.java:50,106-127,148-153,335-338`、`InMemoryRevocationStore.java`
- **描述**：登录失败锁定/登出黑名单/改密令牌失效存本机内存，`failureCount` 无原子同步（并发失败登录 TOCTOU 可绕过锁定）；多实例部署失效不跨节点、进程重启清空。
- **建议**：生产多实例时注入 Redis 实现（类注释已预留）；失败计数用原子自增（`INCR`+`EXPIRE`）。

### 【中】D2-05 家长认领后自建学生未隐藏，视图出现"重复/冗余"
- **位置**：`ParentService.java:224-245`（认领置 `merged=true`）、`:152-164`（`listBinds`）
- **描述**：认领合并后 `listBinds` 仍返回 `origin=self` 的 merged 学生（`merged` 未返回前端），家长可能误以为有两名学生。
- **建议**：`listBinds` 过滤 `merged=true` 的 self 学生，或将 `merged` 返回前端隐藏。

### 【中】D2-06 claimStudent 实际未校验手机号，与注释不符
- **位置**：`ParentService.java:201-217`（仅 studentNo+name+idCardLast8），注释作"学号+姓名+手机号+身份证后8位"
- **描述**：注释声称四要素含手机号，代码未校验 `req.getPhone()`。物理链路有限，但注释误导且缺校验因子。
- **建议**：补 `req.getPhone()` 与绑定家长账号手机号一致性校验，或将注释改为"学号+姓名+身份证后8位"。

### 【低】D2-07 schoolFilterForStatistics 存在不可达分支 + 注释误导
- **位置**：`DataScopeService.java:150-160`（157 行 `return currentSchoolId()`）
- **描述**：`visible==null` 仅 `SCOPE_ALL` 成立，而该分支已先 `if(SCOPE_ALL) return null`；其余角色 visible 均非 null → 直接 return null。故 157 行永不可达，注释"按当前登录校兜底"与实现不符。
- **建议**：删除死分支或用 `if(ALL) return null;` 简写，修正注释。

### 【低】D2-08 courseStats 参考满分仅取首条
- **位置**：`StatisticsService.java:145`（`refFullScore = items.get(0).fullScore`）
- **描述**：同场同科异常不同满分时展示失真（正常不应发生，缺防御）。
- **建议**：取满分众数或校验一致后取首个非空。

## 维度三 · 库表字段

### 【低】D3-01 Grade.full_score 实体可空，与基线「INT N」不符
- **位置**：`Grade.java:44` `@Column(name="full_score") private Integer fullScore=100;`
- **描述**：基线 2.11 要求 `full_score NOT NULL 默认 100`，实体未加 `nullable=false`；`avg(full_score)/得分率`遇 NULL 偏差。
- **建议**：改 `@Column(name="full_score", nullable=false)`。

### 【低】D3-02 SystemSetting.svalue 长度 256 可能不足（基线计划存 JSON）
- **位置**：`SystemSetting.java:30` `length=256`
- **描述**：`std_weights(JSON)` 多科目权重易超 256，单校多科目撑爆。
- **建议**：扩至 `VARCHAR(1024)` 或 `TEXT/JSON`，或拆独立表。

### 【低】D3-03 account.wechat_openid/unionid 预留未约束唯一
- **位置**：`Account.java:61-65`
- **描述**：`unionid` 本应全局唯一，现无唯一索引（未启用可接受），上线微信登录前需加，否则同微信多校重复。
- **建议**：上线前对 `wechat_unionid` 加唯一索引（允许 NULL 多行）。

### 【低】D3-04 id_card_hash 仅后8位 BCrypt，认领/去重能力弱
- **位置**：`Student.java:52/57`
- **描述**：BCrypt 不可逆不可直接比对原文，无法做"按身份证等值认领/去重"。
- **建议**：若需按身份证认领，增可逆比对（AES 解密比对或 HMAC 确定性摘要），认领逻辑注明限制。

> 其余实体字段与基线 2.1–2.12 已逐一比对**一致**（列名/类型/长度/空/唯一/索引），含 `uk_class_school_name`、`uk_course_school_name`、`uk_exam_type_school_name`、grade 八轮 `school_id` 快照与 5 索引。`system_setting` 提前补 `school_id`（超越基线 S2 预留，正向）。

## 维度四 · 索引设计

**正面结论**：`GradeRepository` 核心统计查询索引支撑良好——`stats/scores/rankRows` 匹配 `idx_grade_exam_course_source`；`courseRowsByExam` 匹配 `idx_grade_course_source`；`statsByClass/scoresByClass` 复用 `idx_student_class`；school_id 过滤由 `idx_student_school` 等覆盖。

### 【中】D4-01 tenant 字典表缺 school_id 索引（account / exam 确切实缺）
- **位置**：`Account.java`（仅 username/phone 唯一，无 school_id）、`Exam.java:9-10`（仅 `idx_exam_source_semester`）
- **描述**：`listTeachers` 用 `findByRoleAndSchoolId`、考试按 `(school_id, source)` 查询，现有索引首列是 source 不覆盖 `(school_id, source)`；而 level/class/grade/student 已有 school_id 索引，形成不一致。course/exam_type/class/level 的 `(school_id,...)` 唯一键前导已覆盖，**无需补**（修正了 DB 专家对后几者的泛化判断）。
- **建议**：`Account` 加 `@Index(name="idx_account_school", columnList="school_id")`（或 `(role, school_id)`）；`Exam` 加 `idx_exam_school_source(school_id, source)`。

### 【低】D4-02 冗余索引（与唯一键前缀重复，可安全删除）
- **位置**：`Grade.java:15` `idx_grade_student(student_id)`、`ExamCourseGroup.java:14` `idx_ecg_exam(exam_id)`
- **描述**：前者被 `uk_student_exam_course_source` 首列覆盖，后者被 `uk_exam_course` 首列覆盖，二者为冗余副本，徒增写入开销。
- **建议**：删除 `idx_grade_student`；若需按 `course_id` 查可加 `idx_ecg_course(course_id)`。

### 【低】D4-03 ParentStudentBind 无 student_id 单列索引
- **位置**：`ParentStudentBind.java:8-11`（仅 UK 首列 parent_account_id）
- **描述**：按 student_id 查/删（呼应 D1-02 删学生清理）需全扫描。
- **建议**：增 `idx_psb_student(student_id)`，配套 `deleteByStudentId`。

### 【低】D4-04 GradeRepository.search 仅按 source 过滤时无有效索引
- **位置**：`GradeRepository.java:33-47`
- **描述**：现有索引首列非 source，仅传 source（家长跨考试查全部）会全表扫。
- **建议**：若高频加 `idx_grade_source(source)`；否则调用方强制带 examId/courseId（通常都会带，可降级低优先级）。

依据 = 安全/隔离/数据完整性 × 可达成性 × 影响面：

| 优先级 | 问题 | 级别 | 说明 |
|--------|------|------|------|
| **1** | D2-01 5 处读路径超管被误锁 | 高 | 正确性缺陷，根因是"租户判据未收口到 `isGlobalAdmin()`"。修复成本低、收益高（消除一类系统性误锁，防同类复发），是 DB"口径不一"与后端"误锁"交汇点。 |
