## 二、逐项改动明细

### 批次 A：安全加固（P0/P1）

1. **Cookie Secure 自适应**（`AuthController.java`）
   - 优化内容：`login` 下发令牌 Cookie 与 `logout` 清理 Cookie 在 HTTPS 场景自动追加 `Secure` 标志（经 `request.isSecure()` 判定），纯 HTTP 本地调试不阻塞。
   - 影响范围：认证接口响应头；不影响既有 HttpOnly/SameSite=Lax 语义。
   - 验证方式：不改变 token 解析逻辑，回归测试（AuthFlowTest/LoginLockTest）全绿。

2. **启动器信任边界**（`tools/ServerLauncher.cs`）
   - 优化内容：启动后端前校验 jar 路径字符白名单、端口范围、profile 合法性；JRE 自动下载仅允许 `https://` 源且下载后若存在 `<jar>.sha256` 则强制比对哈希；self-check 汇总处对「非生产且未注入 APP_SECURITY_TOKEN_SECRET/APP_CRYPTO_KEY」给出演示密钥醒目告警。
   - 影响范围：仅启动器启动路径；不改变已发布 jar/ini 该有的行为（无 `.sha256` 时仍放行，保证单机免配）。
   - 验证方式：csc 重编 RC=0，EXE_EXISTS=True；自我检查日志输出 `[SEC]` 告警。

3. **保留取舍**：未对 `ProductionGuard` 强加「H2 非 localhost 必填密钥」fail-fast，避免破坏单机免配分发，改为启动器告警提示。

### 批次 B：家长跨校排名修复（P0）

4. **家长名次按归属校重算**（`RankingService.java`）
   - 优化内容：家长路径若绑定学生归属校存在，则用 `gradeRepository.rankRows(examId, courseId, source, parentSchoolId)` 按本校集合重建排名，避免展示跨校全局名次；无/跨校保守放行（不丢数据）。抽出 `buildRankedRows` 复用，杜绝双实现漂移。
   - 影响范围：仅家长可见名次/档位计算；老师路径不变。
   - 验证方式：`mvn compile` RC=0；ParentRankPrivacyTest 全绿。

### 批次 C：统计口径与多租户过滤（P1）

5. **及格/优秀/分数段阈值改用原始分**（`StatMath.java`）
   - 优化内容：`ScoreItem` 新增 `rawPercent`（未四舍五入），`isPass/isExcellent/distribution` 基于原始 `score*100.0/full` 判定，消除 `[59.95,60)`、`[84.95,85)` 边界误判；展示仍用四舍五入值。
   - 影响范围：统计的及格线/优秀线/分布判定；不影响数值展示与标准分。
   - 验证方式：StatisticsMetricTest 全绿；`mvn compile` RC=0。

6. **双来源重复计数剔除**（`StatisticsService.java`）
   - 优化内容：`studentMultiSubject` 的 `stdItems` 仅收入 `GradeSources.TEACHER` 来源，与 `totalScore` 口径一致，消除同场同科 teacher+parent 双成绩被双重计数。
   - 影响范围：多科汇总标准分；`studentTrend`（本已正确）不受影响。
   - 验证方式：`mvn compile` RC=0；回归全绿。

7. **学期维度按校过滤**（`ExamRepository.java` + `ComparisonService.java` + `TrendService.java`）
   - 优化内容：`findBySourceAndSemester` 增加 `@Param("schoolId")` 可选过滤（`(:schoolId is null or e.schoolId = :schoolId)`），供 `ComparisonService`/`TrendService` 传入 `schoolFilter`，避免返回跨校考试 ID 进入对比/趋势基线。
   - 影响范围：按校隔离的对比、趋势查询；null 时行为不变（全局超管/兜底放开）。
   - 验证方式：`mvn compile` RC=0；SettingsAndAnalysisTest 全绿。

### 批次 D：技术债清理与代码质量（P2，本次）

8. **启动器校验方法纯函数化**（`tools/ServerLauncher.cs`）
   - 优化内容：`VerifyJarChecksumOptional` 移除内部的 `jarOk=false` 副作用赋值，改为纯返回 bool；`jarOk` 统一由调用方 `CheckJar` 依据返回值置位，消除双重赋值混淆。
   - 影响范围：仅启动器的 jar 完整性判定路径；校验逻辑与结果不变。

   - 影响范围：仅默认密码推导路径；`decrypt` 主方法契约不变（EncryptBindTest 不受影响）。
   - 验证方式：`mvn compile` RC=0；EncryptBindTest 全绿。

10. **批量录入返回明细**（`GradeService.batchCreate` + `GradeController` + `GradeServiceTest`）
    - 优化内容：`batchCreate` 返回 `{created, skipped, skippedDetails[]}`（含每行 studentId/examId/courseId/reason），避免静默掩盖录入丢失；控制器直接返回该明细。
    - 影响范围：`POST /api/grades/batch` 响应结构由 `{created}` 扩展为明细（新增字段，兼容旧字段）；测试同步更新断言。
    - 验证方式：GradeServiceTest「批量录入超额分数被跳过」断言 `created=1, skipped=1` 通过；`mvn test` 全绿。

11. **schoolId 取数统一复用**（`DictionaryService`/`SettingsService`/`LevelService`/`ExamService`）

    - 验证方式：`mvn compile` RC=0；`mvn test` 全绿（含 MultiTenantTeacherPhaseATest、SchoolLevelMultiTenantTest 等）。

## 三、保留/取舍决策

- **ProductionGuard**：不对 H2+非 localhost 强加密钥必填（保持单机免配可启），以启动器 `[SEC]` 告警兜底提示。
- **AesCrypto.decrypt**：主方法保留「解密失败抛异常」（作为真·数据损坏信号），另提供 `decryptSafe` 供可降级场景；避免掩盖真实加密故障。
- **wechat 占位端点**：保留端点，沿用 `BizException("微信登录尚未启用…")` 返回友好业务错误（比 `UnsupportedOperationException` 触发 500 更优），契约文档已更正为「需 token 的占位接口」。
