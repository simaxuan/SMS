## 0. 执行摘要

本项目主体功能闭环度约 **80%~85%**：老师端（学生/成绩录入/成绩查询/单科统计/趋势）与家长端（绑定/趋势/小测）核心链路可用，来源隔离与权限校验严谨。但存在 **5 项直接影响上线体验的功能短板**，以及若干体验细节问题。本方案给出 **P0/P1/P2 三级 16 项优化建议**，其中多数可直接基于现有表结构与权限体系落地，无需大改。

**三方交叉确认的最高优先级短板（P0）**（以下为 v20.0 当时状态，截至 v5 均已落地，见各节「现状」标注与文末清单）：
1. ~~考试管理无前端 UI~~ → ✅ 已落地（Exam.vue + 路由，第三轮）
2. ~~多维度对比（需求 UC-503）占位未实现~~ → ✅ 已落地（StatisticsService.comparison 真实聚类对比，第三轮）
3. ~~无成绩导出/打印能力~~ → ✅ 已落地（GradeQuery.vue 导出 CSV + 打印，第三轮）

5. ~~缺排名/进步/预警等"洞察"~~ → ✅ 已落地（Statistics.vue 排名/进步退步/预警，第三轮）

## 2. 使用价值与薄弱环节（价值员核心结论）

### 2.1 高价值功能（维持并强化）
- **成绩录入**（老师）：高使用频率，唯一性/分值校验到位，是系统基石。
- **成绩统计**（老师）：得分率相对口径（兼容 100/120 满分）是正确且少见的设计亮点。
- **孩子趋势 + 小测**（家长）：来源隔离清晰，家长录入小测不进班级统计，符合"个人版自测"定位。
- **空状态引导**（el-empty）、**越权 403 防护**、**错误文案友好**：体验亮点，应保持。

## 5. 关键新增模块详细设想（重点）

### 5.1 多维度对比模块（P1，兑现 UC-503）【✅ 已落地：第三轮 StatisticsService.comparison 真实聚类对比 + Statistics.vue 对比 Tab】
- **班级对比**：选「考试+课程」→ 按 `Student.classId` 分组 → 各组均分/及格率/优秀率/分布 → ECharts 分组柱状图 + 雷达图。
- **多次考试对比**：选「班级+课程+多个 examId」→ 横向展示各次平均得分率折线，揭示该班该科走势。
- **落地**：后端 `statsByClass`（JOIN Student GROUP BY classId）+ 跨 exam 循环聚合；`StatisticsController` 扩展 comparison 入参 `(examId, courseId, classIds?, examIds?)` + `requireRole(TEACHER)`；前端 Statistics.vue 加 Tab。**仅扩展聚合维度，不破坏现有唯一约束与权限。**

### 5.2 排名与进步/退步分析（P0/P1）
- **单科排名**：同 (examId,courseId,source=teacher) 按 score 降序（含并列名次）。
- **总分排名**：同 (examId,source=teacher) 按学生总分降序。
- **进步榜/退步榜**：相邻两次考试同课程得分率 delta 排序。
- **落地**：`GradeRepository.rankByExamCourse(...)` 返回有序 (studentId,score)，Service 映射名次；全部基于现有 grade/student/exam 字段，**派生数据实时计算，无新表**；权限沿用 teacher 来源过滤。前端 StudentTrend/GradeQuery 加名次列与进退步区块。

### 5.3 考试管理页（P0，阻断主流程的补全）【✅ 已落地：第三轮新增 Exam.vue + 路由 /exams】
- 新建 Exam.vue：列表+新增/编辑（名称、关联考试类型、考试日期）+删除（引用保护已由 `existsByExamId` 后端保证）。
- 路由 `/exams`（老师角色），菜单挂到"基础数据"或独立入口。
- **后端零改动**（exams CRUD 已完备），**纯前端补齐**，收益立现。

## 7. 决策需确认项（产品拍板）

1. **排名隐私**：家长端是否展示孩子班级/年级排名？文档要求"可配置开关"，建议默认关闭、老师端可开。→ ✅ **已闭环（v5）**：`parent_rank_detail` 默认 `aggregate`（仅本人名次 + 班级/级部聚合，不返回全班明细）；另有 `limited`/`full`（仅 ALL 角色）档位。
2. **总分口径**：跨考试总分是否由"累加原始分"改为"总得分率/标准分"？（涉及历史数据显示口径）→ ✅ **已闭环（v5）**：三口径并存——`totalScore`（原始分累加，主展示）/ `totalPercent`（总得分率）/ `stdScore`（标准分，equal/full-weighted/custom-weighted），跨考试可比，非简单替换原始分。
3. **家长小测建模**：是否将"自定义小测"与校内考试彻底解耦（独立小测表）？短期可用下拉独立项，长期建议独立建模。→ ⏳ **保留下一步决策**：短期 `Exam.source='custom'` 下拉独立项已落地（第三轮）；长期独立小测表未决策。
4. **知识点题型**（C4）是否纳入规划——工程量大，且当前需求未明确到该粒度。→ ⏳ **保留下一步决策**：已出《知识点题型维度-详细设计方案》（设计稿，暂不建表）；是否纳入与何时建表待产品评审。
