## 一、缺陷背景

上一轮审计中，`MultiTenantPhaseBTest` 与 `MultiTenantTeacherPhaseATest` 等测试类暴露出 **5 个多租户隔离失败用例**，覆盖三类典型越权/隔离缺失场景：

| 编号 | 场景 | 失败表现 |
|------|------|----------|
| B1 | 排名 scope 隔离 | SCOPE_ALL 超管读取排名未按登录校收敛，跨校数据混入 |
| B3 | system_setting 隔离 | 系统设置未按登录校隔离，超管读到他校配置 |
| B4 | 写路径跨校 | 写路径信任请求体 schoolId，普通角色可跨校写入 |
| 老师读路径 | 字典/学生/考试读路径 | 超管带登录校时仍放开全校，越权读取他校班级/学生/考试 |
| 级部 update | 级部级联归属 | 级部/班级归属校验不足以阻止跨校引用 |

**根因判定**：旧 `SCOPE_ALL` 语义不统一——读路径一律放开全校、写路径信任请求体、且 `DictionaryService.listClasses()` 完全不过滤学校（`return classRepository.findAll()`）。这与测试契约要求的「超管带登录校即按校收敛、仅 true-global 放开」相冲突。

---

## 二、统一修复口径（核心决策）

确立全系统一致的多租户收敛规则：

> **带登录校即按校收敛；仅 `schoolId == null` 的「真全局超管」放开全校；跨校查看统一由显式 `schoolId` 参数或前端切换登录校完成。**

该口径推翻旧设计（旧：`isGlobalAdmin()` 一律放开全校 / 写路径信任请求体），与全部隔离测试断言契约对齐。

关键方法语义（`DataScopeService`）：
- `resolveWriteSchoolId(Long)`：SCOPE_ALL 带登录校 → 强制登录校；仅 true-global（schoolId 空）才信任请求体跨校写。
- `effectiveSchoolId()`：移除 `SCOPE_ALL→null` 分支，直接返回登录校；true-global 返回 null 放开。
- `schoolFilterForStatistics(Account)`：`visible == null`（SCOPE_ALL）时按登录校兜底，非 null 返回 null。

## 三、改动文件清单

| 文件 | 改动要点 |
|------|----------|
| `service/DataScopeService.java` | `resolveWriteSchoolId` / `effectiveSchoolId` / `schoolFilterForStatistics` 统一「带登录校即收敛」口径 |
| `service/SettingsService.java` | `currentSchoolId()` 私有方法去除 `isGlobalAdmin()?null:...` 豁免，改调 `dataScopeService.currentSchoolId()`（B3 修复） |
| `service/StudentService.java` | `getById` 去除 `isGlobalAdmin()` 豁免，只要 `schoolId != null` 即强校验同校（消除 IDOR 越权读） |
| `service/ExamService.java` | `list()` 改用 `effectiveSchoolId()`；`getById` 去除 `isGlobalAdmin()` 豁免，同校强校验 |
| `service/DictionaryService.java` | `listClasses` 拆分为**无参（按登录校收敛）** 与 **`Long` 参数（SCOPE_ALL 显式跨校）** 两个重载；`listCourses` / `listExamTypes` 去除 `isGlobalAdmin()` 放开分支，统一 `effectiveSchoolId()`；`createClass`/`updateClass` 增加 level 归属校一致性校验（B4 防跨校级部引用） |
| `service/StatQuerySupport.java` | `visibleGrades` 去除 `isGlobalAdmin()` 豁免，只要 `schoolId != null` 即强校验同校（消除 IDOR 跨校成绩读取） |

> **兼容性修复（本轮）**：上一轮将原本无参的 `listClasses()` 误改为仅带 `Long` 参数签名，导致 `MultiTenantTeacherPhaseATest.java:121` 编译失败（测试以无参调用）。已恢复无参重载（委托 `listClasses(effectiveSchoolId())`），控制器与超管跨校入口的 `Long` 重载保持不变，向后兼容。

## 五、遗留与后续依赖

1. **前端登录校切换依赖**：新口径下，超管跨校查看/操作必须前端切换登录校（重新下发携带目标 `schoolId` 的 JWT），或显式传 `schoolId` 参数。当前交付以后端测试契约为准，前端切换能力需在 UI 层配套（涉及前端登录态与令牌刷新）。
2. **D1-01 物理外键**：仍未实施，建议并入后续专项（与级联删除逻辑一并评估，避免破坏现有 `deleteClass` 级联清理）。
3. **true-global 放开全校场景**：仅限 `schoolId == null` 的全局超管，生产环境应谨慎配置此类账号。
