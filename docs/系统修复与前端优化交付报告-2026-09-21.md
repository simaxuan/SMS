## 一、后端修复（功能缺陷 / 逻辑错误 / 一致性）

### 1.1 全局超管误锁演示学校（严重度：高）

**问题根因**：`DataSeeder` 给全局超管 `admin` 设置了非空的 `schoolId`（演示校），而多处代码用 `user.getSchoolId() != null` 来判定"是否按单校下推"，导致 SCOPE_ALL 超管被错误锁死在演示学校——级部/班级/课程建不到新学校，读路径（学生/考试/成绩/学期/对比）也被锁演示校。

**修复策略**：以"scopeType 而非 schoolId 是否为空"作为超管识别依据，新增权威方法并统一替换散落的 `user.getSchoolId()` 判定。

| 位置 | 修复前 | 修复后 |
|------|--------|--------|
| `DataScopeService` | 无统一读路径取值；多处手写 `user.getSchoolId()` | 新增 `effectiveSchoolId()`：`SCOPE_ALL` 返回 `null`（放开全校），其他返回登录校；`schoolFilterForStatistics` 移除不可达分支 |
| `StudentService.list` | `currentSchoolId()`（超管被锁演示校） | `studentRepository.search(effectiveSchoolId(), …)` |
| `StudentService.getById` | 有归属校即跨校拦截（超管误判） | 跨校拦截外包裹 `!dataScopeService.isGlobalAdmin()` |
| `StudentService.apply` | 超管建学生回填 `user.getSchoolId()`（演示校） | `isGlobalAdmin()` 且请求体未显式指定时保持 `null`（放开全校） |
| `ExamService.getById/list/create` | 同上 | `getById` 跨校校验包裹 `isGlobalAdmin()`；`create` 用 `resolveWriteSchoolId(req.getSchoolId())` 跨校建考试 |
| `ComparisonService.semesters` | `currentSchoolId()`（锁演示校） | `effectiveSchoolId()` |
| `StatQuerySupport.visibleGrades` | 有归属校即拦截 | 跨校拦截包裹 `isGlobalAdmin()` |
| `GradeService.list` | `currentSchoolId()` 兜底 | `schoolFilterForStatistics(user)`（超管= `null` 放开全校） |

### 1.2 删除级联安全网缺口（严重度：高）

**问题**：删除父实体时未清理从属/孤儿数据——软删学生未清家长绑定（孤儿绑定）、删考试未清科目组合（ECG 孤儿）、删学校未校验系统设置，存在数据残留与越权隐患。

**修复**：

| 文件 | 改动 |
|------|------|
| `ParentStudentBindRepository` | 新增 `deleteByStudentId(Long)`、`deleteByParentAccountId(Long)` |
| `SystemSettingRepository` | 新增 `existsBySchoolId(Long)`、`deleteBySchoolId(Long)` |
| `ParentPreferenceRepository` | 新增 `deleteByParentAccountId(Long)`（账号删除能力预留） |
| `StudentService.delete` | 软删后调用 `bindRepository.deleteByStudentId(id)` 清理孤儿绑定 |
| `ExamService.delete` | 删考试前调用 `courseGroupRepository.deleteByExamId(id)` 清理 ECG |
| `SchoolService.assertNoDependencies` | 增加 `systemSettingRepository.existsBySchoolId(schoolId)` 校验，删除学校前拒绝残留 |

### 1.3 并发与一致性（严重度：中）

| 文件 | 改动 | 效果 |
|------|------|------|
| `Grade` | 新增 `@Version private Long version` 乐观锁字段 | 并发更新同一条成绩时版本冲突抛 `OptimisticLockException` |
| `GradeService` | `update`/`batchCreate` 捕获 `DataIntegrityViolationException`（唯一键冲突→409）与 `ObjectOptimisticLockingFailureException`（并发覆盖→"请刷新后重试"） | 并发录入/改挂不再 500，转为友好提示 |
| `ParentService.createSelfStudent` | `"SELF"+System.currentTimeMillis()` → `"SELF"+UUID…substring(0,10)` 并捕获 `DataIntegrityViolationException` | 消除高并发下时间戳碰撞导致的唯一键冲突 |

### 1.4 其他一致性修正

- `ParentService.listBinds` 跳过 `merged=true` 的自建学生，避免双账号共享编辑场景下重复展示。
- `ParentService.claimStudent` 注释纠正，移除"会校验手机号"的错误描述（实际未做该校验）。
