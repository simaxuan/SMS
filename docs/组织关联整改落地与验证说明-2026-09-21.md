## 二、后端改动清单

### 1. `DataScopeService.java`（治本，总根因）
- 新增 `isGlobalAdmin()`：按 `scopeType=ALL` 判定全局超管（而非仅 `schoolId==null`）。
- 新增 `resolveWriteSchoolId(Long requestedSchoolId)`：全局超管信任请求体可跨校指定 schoolId；带归属校的普通老师（CLASS/SCHOOL）强制锁定登录校；无登录校回退请求体。
- `schoolFilterForStatistics()`：全局超管放开全校，不再收敛到登录校（消除统计误伤）。

### 2. `LevelService.java`（P0-1 级部挂新校）
- `create()`：`schoolId = resolveWriteSchoolId(req.getSchoolId())`，超管建级部挂到请求所选新学校。
- `update()`：同样统一决策，超管可迁移级部归属，避免把他校级部重挂演示校。

### 3. `DictionaryService.java`（P0-2 / P1-4 / P1-5 / P2-8）
- `listClasses(Long schoolId)`：超管放开全校并按参数筛选；普通老师锁定登录校。
- `createClass()` / `updateClass()`：改用 `resolveWriteSchoolId`，班级可挂到指定学校+级部。
- `listCourses()` / `listExamTypes()`：超管放开全校。
- `createCourse()` / `createExamType()`：超管可显式指定 schoolId 跨校建档；普通老师锁定登录校。
- `updateCourse()` / `updateExamType()`：超管放开跨校编辑。
- `deleteClass()`：删除前清理该班级的 teacher_class 归属（防悬空）。

### 4. `AuthService.java`（P1-4）
- `listTeachers()`：全局超管返回全部学校老师（可跨校选择/管理）。

### 5. DTO（P1-5）
- `CourseRequest`、`NameRequest`：新增可空 `schoolId` 字段。

### 6. Repository / 删除安全网（P2-8）
- `TeacherClassRepository`：新增 `deleteByClassId`。
- `ExamCourseGroupRepository`：新增 `existsBySchoolId`。
- `SchoolService.assertNoDependencies`：补充 `exam_course_group` 存在性校验。

## 三、前端改动清单

### 1. `api/index.js`
- `dictApi.classes` 支持 `schoolId` 查询参数。

### 2. `Dictionary.vue`（P0-2 / P1-5）
- 班级管理：新增/编辑对话框增加"归属学校 + 归属级部"下拉，提交 `name/schoolId/levelId`；列表新增"归属学校/归属级部"列。
- 课程 / 考试类型：对话框增加"归属学校"选择（超管跨校指定，普通老师留空由后端推导），列表显示归属。
- 级部下拉按所选学校联动加载。

### 3. `Organization.vue`（P2-7 / 联动优化）
- 新建学校成功后自动把级部管理下拉切换到新学校，便于直接挂接级部。
- 老师-班级归属、教师创建的班级下拉**按老师所选学校过滤**，避免跨校误绑。

## 四、修复后的工作流（用户可验证）

1. **全局管理员**登录 → 组织管理「学校管理」新增学校（如"二中"）→ 级部下拉自动切到"二中"。
2. 「级部管理」新增级部（如"初一年级"）→ 后端按请求体 schoolId 挂到"二中"。✅（原：挂到演示学校）
3. 「词典-班级管理」新增班级 → 选归属学校"二中"+ 归属级部"初一年级" → `level_id/school_id` 正确落库。✅（原：level_id 恒空）
4. 「组织管理-教师管理」新增老师（归属"二中"）→「老师班级归属」给该老师绑定"二中"的班级（下拉已按校过滤）→ 老师→班级→级部("二中/初一年级") 通路打通。✅（原：选不到新校班级）

## 六、未落地项（后续建议，本轮有意暂缓）

| 项 | 说明 | 原因 |
|----|------|------|
| `Grade.school_id` 非空约束/背靠校验 | 消除 NULL/错校孤儿成绩 | 涉及 JPA 建表与历史数据迁移，需先对齐《第六轮DDL基线》 |
| `teacher_class` 增加 `school_id` 冗余列 | 简化"某校/某级部全部老师"查询 | 涉及现有数据回填与查询改造，风险较高 |
| `teacher_level`（老师-级部直接关系表） | 支持"级部直接挂老师" | 本期产品设计为"老师→班级→级部"间接归属，属功能增强非缺陷 |
| 前端统一组织树 | 学校→级部→班级→老师 一级视图 | 交互重构，工作量较大 |

> 建议后续按 DDL 基线评审后单独立项处理上述数据层项，避免与本次组织挂接修复混合引入回归。
