# 个人版 / 校园版：需求与技术实施方案

> 本文是本期开发蓝本。整合已确认决策 + 统计维度差异分析，明确「表结构 / API / 权限 / 前端 / 分期」，供开发落地与验收对齐。**第六轮 v5 已定稿，已补充：多租户组织建模、统计三口径、AES 加密与绑定四要素、家长排名隐私、微信/短信预留（详见各节「v5」标注）。**

## 1. 已确认决策（硬约束）

| # | 决策 | 落实 |
| ---- | ---- | ---- |
| 1 | 家长绑定学生 = **学号 + 姓名 精确匹配** | `parent_student_bind` 绑定接口（**v5 升级四要素**） |
| 2 | **不独立部署**，登录页**选择老师/家长**角色 | 单 jar + 登录页角色选择（多校为单库 `school_id` 逻辑隔离） |
| 3 | 家长录入成绩**无需老师端审核**（在家自学/小测性质） | `grade.source='parent'` 直接入库，不建审核态 |
| 4 | 老师端**不看、不统计**家长录入成绩 | 老师端查询/统计一律 `source='teacher'` |
| 5 | 家长录入的成绩仅**本人**可改可删；老师成绩家长**只读** | 来源 + 属主 + 数据范围双重校验 |
| 6 | **两端统计维度不同** | 后端分 `teacher/*` 与 `parent/*` 两套统计接口（见《统计维度差异分析》） |
| 7（v5） | 绑定四要素 = 学号+姓名+手机号+身份证后8位(+密码)；默认密码=身份证后8位，**不强制首改**；恢复默认密码仅老师操作 | `BindRequest` 四要素 + AES/BCrypt + 老师端重置 |
| 8（v5） | 多租户：`school`/`level` 独立表 + `teacher_class`；三级范围 class/level/school 排名 | `DataScopeService` 三级范围 + school_id 强隔离 |
| 9（v5） | 统计三口径并存：总分/总得分率/标准分（equal/full-weighted/custom-weighted，默认 equal，本期开放 custom） | `StatisticsService` 三指标 + `exam_course_group` |
| 10（v5） | 家长排名隐私：默认 `aggregate`（本人名次+班级/级部聚合），不再返回全班明细 | `ranking()` 家长分支 + `parent_rank_detail` |
| 11（v5） | 登录：学生姓名+手机号+密码；失败锁定固定 5 次/15 分钟；微信仅占位 | `AuthController` + `LoginLock` + `/api/auth/wechat` 占位 |

## 2. 角色与登录

### 2.1 账号模型
```
account
  id, username(unique), password_hash, role, nickname, created_at
  -- v5 新增：phone(unique, 家长登录名), school_id, scope_type(CLASS/ALL),
  --          wechat_openid, wechat_unionid, auth_type, last_password_change
role ∈ { TEACHER, PARENT }
```
- 密码 BCrypt 哈希（用 spring-security-crypto 的 BCryptPasswordEncoder，轻量不引入完整 Security）。
- 老师账号：管理员预置（本期提供注册接口，首启预置一个 admin 老师账号便于测试）。
- 家长账号：自助注册（**v5**：可带 `phone`；默认密码 = 身份证后 8 位，不强制首改）。

### 2.2 登录与鉴权
- `POST /api/auth/login { username, phone, password, role }` → 家长=`学生姓名`+`手机号`+`密码`；校验角色与密码 → 返回 `token` + 用户信息（id/username/nickname/role/schoolId/scopeType/phone）。
- **v5 失败锁定**：连续失败固定 **5 次/15 分钟**（硬编码，不配置化），期间拒绝登录。
- token：内存 Map<token, account> 的简化方案（单机可接受，重启失效）。`X-Token` 头部携带。
- 拦截器 `AuthInterceptor`：解析 token → 存入 `LoginUserContext`（ThreadLocal）。未登录访问受保护接口返回 401。
- 角色鉴权：接口层用简单 `@RequireRole("TEACHER")` 注解 + 拦截器检查，或控制层判断。
- **v5 微信预留**：`POST /api/auth/wechat` 仅占位返回「未启用」，预留 `wechat_openid/unionid/auth_type` 字段，不做鉴权与绑定 UI。

### 2.3 注册
- `POST /api/auth/register`（role=PARENT，家长自助注册，可带 phone）
- `POST /api/auth/register`（role=TEACHER，仅管理员权限或预置；本期为便于联调允许注册 TEACHER）

## 3. 家长-学生绑定

```
parent_student_bind
  id, parent_account_id, student_id, relation(father/mother/other), created_at
  unique(parent_account_id, student_id)
```
- `POST /api/parent/bind { studentNo, name, phone, idCardLast8, relation, password }` → **v5 四要素**：学号+姓名 + 手机号(与父/母手机号匹配) + 身份证后8位(hash 比对) → 校验重复绑定 → 建立绑定 + 设置默认密码（后8位 BCrypt）。
- `GET /api/parent/binds` → 当前家长绑定列表（含学生信息）。
- `DELETE /api/parent/binds/{studentId}` → 解绑（可选）。
- **v5 双父母**：双账号各绑定同一学生，信息/编辑一致（可编辑全量 parent 成绩，teacher 只读），保留 `creator_account_id` 审计；**恢复默认密码仅由老师端操作**（审计留痕）。
- **v5 加密**：`student.id_card` AES 加密、`id_card_hash`=BCrypt(后8位)，明文不返回。

## 4. 成绩来源隔离（核心）

```
grade 新增：
  source            -- 'teacher' | 'parent'（默认 'teacher'）
  creator_account_id -- 录入人账号（家长来源必填；老师来源=当前老师）
-- grade 表不加 school_id 冗余；school 经 student.school_id 推导（查询 join 校验一致）
```

### 4.1 权限矩阵
| 操作 | 老师 | 家长 |
| --- | --- | --- |
| 可见成绩 | 全校 **source=teacher** | 绑定学生的 `teacher`(只读) + 自己 `parent` |
| 录入 | 全校，`source=teacher` | 绑定学生，`source=parent` |
| 修改/删除 | teacher 来源全部 | **仅自己录入的 parent**；teacher 来源只读 |
| 统计 | 全校 teacher | 绑定学生（teacher+own parent，图例区分） |

### 4.2 实现要点
- `GradeService` 增加「当前登录用户 + 数据范围」校验：家长写入只允许绑定学生；家长改删仅限 `creator_account_id=本人`。
- `GradeRepository` 查询按角色注入过滤：老师 `source=teacher`；家长按 `studentId in (绑定学生)`。
- `StatisticsService` 老师统计过滤 `source=teacher`；家长统计按绑定学生范围。
- 前端隐藏不可操作按钮（后端仍强制校验，防止越权）。

## 4.3 统计三口径（v5 已定稿）

- **总分 `totalScore`** = `Σscore`（原始分累加，主展示）。
- **总得分率 `totalPercent`** = `Σscore/Σfull×100`（跨考试可比）。
- **标准分 `stdScore`** = 各科得分率均值加权：
  - `equal`（默认）：`mean(各科 score/full×100)`；
  - `full-weighted`：`Σscore/Σfull×100`（≡ totalPercent）；
  - `custom-weighted`：`Σ(得分率×w_i)/Σw_i`，权重由 `system_setting.std_weights` 配置（**本期开放**）。
- 多科总分经 `exam_course_group`（`active` 标记计入科目）计算；缺考/无效科目不进分母；空数据 `stdScore=null`。
- **家长排名隐私**：`ranking()` 家长分支按 `parent_rank_detail`（默认 `aggregate`）仅返回本人 `{rank,score,percent,className,total}` + 班级/级部聚合，不再返回全班明细。

## 6. 前端设计

- **登录页** `/login`：用户名/密码 + **角色选择（老师/家长）**。
- **路由守卫**：未登录跳 `/login`；已登录按角色重定向默认页（老师→/dashboard，家长→/parent-dashboard）。
- **家长端**（新增父布局或复用）：
  - 绑定管理页：学号+姓名绑定。
  - 成绩查看：仅绑定学生；表格中标示「老师/家长」来源，老师成绩只读。
  - 录入：仅绑定学生，`source=parent`。
  - 趋势：调 `student-trend` 个体轨迹。
- **老师端**：现有全部页面（未登录前不可直达）。
- token 存 localStorage，axios 请求头带 `X-Token`。

## 7. 数据库：H2 create-drop（实体驱动，随 DataSeeder 建表）
- 已实现实体：`Account`、`ParentStudentBind`；`Grade` 加 `source`、`creatorAccountId`。
- **v5 新增实体/字段**（据《统一数据库字段规范-第六轮DDL基线》）：
  - 新表：`school`（多租户根）、`level`（级部）、`teacher_class`（老师-班级）、`exam_course_group`（考试-科目组合）。
  - `account`：`+ phone` `+ school_id` `+ scope_type` `+ wechat_openid` `+ wechat_unionid` `+ auth_type` `+ last_password_change`。
  - `student`：`+ id_card(AES)` `+ id_card_hash` `+ father_phone` `+ mother_phone` `+ origin` `+ parent_owner_account_id` `+ enrolled` `+ merged` `+ school_id`。
  - `class_entity`：`+ level_id` `+ school_id`；`course`/`exam_type`/`exam`：`+ school_id`。
  - `system_setting`：新增 `parent_rank_detail`、`std_weight_mode`、`std_weights`。
  - `grade`：不加 school_id 冗余，经 student 推导。
- DataSeeder 预置：1 个老师账号（如 admin/admin123 依赖角色选择）、1 个测试家长账号，并预置几条 parent 来源成绩以演示隔离。

## 9. 风险与注意
- 内存 token 重启失效：单机可接受；后续可换 JWT。
- 家长绑定需精确匹配学号+姓名，重复/不存在需友好提示。
- 后端必须强制数据范围，不能只靠前端隐藏。
- 老师录入成绩如需「不可修改」语义用于家长侧：`source=teacher` 在家长接口一律只读即可，不改老师自身权限。
