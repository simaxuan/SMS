# 隔离口径一致性遗留修复交付报告

- **日期**：2026-09-21
- **项目**：考试成绩分析系统（Spring Boot 3.2.5 + JPA + 多租户 school_id 逻辑隔离）
- **任务来源**：用户要求「修复测试过程又发现遗留问题，请一并处理」。即在上轮统一 `SCOPE_ALL` 隔离口径、使 `mvn test` 全绿（76/0/0）之后，进一步清理仍与新口径冲突的残留分支。
- **验证结论**：`mvn test -Dfrontend.bundle.skip=true` → **Tests run: 77, Failures: 0, Errors: 0, Skipped: 0，BUILD SUCCESS**（新增 B6 验证用例 1 项，原 76 项无回归）。

---

## 一、发现的遗留问题

上轮统一口径后，主代码中仍残留 3 处与「SCOPE_ALL 带登录校即收敛、写路径不信任请求体」冲突的自定义分支，构成跨校写入/编辑缺口：

| 位置 | 旧实现 | 问题 |
|------|--------|------|
| `StudentService.apply:121` | `if (isGlobalAdmin()) { if(req.schoolId!=null) set; else 保持null }` | SCOPE_ALL 超管（含带登录校）可经 `req.getSchoolId()` 把学生建到任意学校，违背"写路径不信任请求体"，形成跨校写入缺口。 |
| `DictionaryService.updateCourse:171` | `if (!isGlobalAdmin()) { 校验归属 }` | 任何 SCOPE_ALL 超管可改**任意学校**的课程，与 create 路径"锁定登录校"不一致。 |
| `DictionaryService.updateExamType:219` | `if (!isGlobalAdmin()) { 校验归属 }` | 同上，考试类型跨校编辑缺口。 |
| `StudentService:39` 注释 | "effectiveSchoolId 对超管返回 null（放开全校）" | 注释与已改动的 `effectiveSchoolId()` 实现不符（现返回登录校），文档遗留。 |

> 检索确认：改动后主代码中 `isGlobalAdmin()` 仅剩 `DictionaryService.listClasses(Long)` 跨校入口这一处**有意保留**用途（供超管显式跨校查看），以及 `DataScopeService` 定义本身，已无违规分支。

---

## 二、修复方案

统一调用中央方法，消除自定义分支：

1. **`StudentService.apply`**：删除 `isGlobalAdmin()` 自定义分支，改为 `s.setSchoolId(dataScopeService.resolveWriteSchoolId(req.getSchoolId()))`（保留 `if (s.getSchoolId()==null)` 仅首次建校，避免更新时误改归属）。
   - SCOPE_ALL 带登录校 → 强制登录校（忽略请求体，关闭跨校写入缺口）；true-global → 信任请求体或保持 null 放开全校；普通老师 → 锁定登录校。
2. **`DictionaryService.updateCourse`**：将 `!isGlobalAdmin()` 放开分支替换为 `Long eff = effectiveSchoolId(); if (eff != null && !eff.equals(c.getSchoolId())) throw 403`。SCOPE_ALL 带登录校仅可改本校课程，true-global 放开全校。
3. **`DictionaryService.updateExamType`**：同理，且对 `schoolId==null` 的全局类型允许编辑（`eff != null && t.getSchoolId() != null && ...`）。
4. **`StudentService:39` 注释**：更正为「effectiveSchoolId 对 SCOPE_ALL 带登录校返回登录校（按校收敛），true-global 返回 null 放开全校」。

## 三、验证测试（新增 B6）

在 `MultiTenantPhaseBTest` 新增 `B6_写路径不信任请求体_学生与课程归属锁定登录校`：
- 以 SCOPE_ALL 带登录校 A 的管理员身份，请求体恶意指定他校 `other`，断言 `studentService.create` 产出的学生 `schoolId == A`（强制登录校）。
- 断言该管理员调用 `updateCourse(他校课程)` 抛出 403「无权修改其他学校的课程」。

运行结果：B6 通过，全量 77 项 0/0/0。

> 回归安全说明：`EncryptBindTest` 以种子 admin（SCOPE_ALL、schoolId=演示校非空）建学生且未断言 schoolId；改动后该校学生正确归属登录校而非 null，不破坏其断言。`B4` 用例仅覆盖 create 路径，不触及 update，无影响。

## 四、仍遗留 / 需单独立项项

1. **前端登录校切换配套**：后端已收敛，超管跨校仍需前端「切换登录校重发 JWT」配套（涉及前端登录态与令牌刷新，建议交 UI 专家）。
2. **D1-01 物理外键**：仍仅应用层约束，未加 DB FK；属大重构，需先对齐《第六轮DDL基线》单独立项。
3. **DataSeeder 给 admin 设非空 schoolId（演示校）**：种子数据选择，新口径下 admin 收敛到该登录校，跨校需切换登录校，非缺陷。
