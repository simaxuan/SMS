## 二、逐维度发现

### 维度① 安全攻防（评分 6.0）

**【高·已知取舍但真实可利用】默认部署姿态薄弱**
- `JwtUtil.java:39` 默认密钥 `local-demo-secret-change-me-7f3b8`，仅 `ProductionGuard.java:53` 在 prod/pg 才 fail-fast；启动器默认 H2（非 prod），`application.yml:35` 默认注入该密钥 → 局域网默认可伪造 admin JWT 接管。
- `AesCrypto.java:24` 演示密钥同理。

**【中】传输与绑定暴露面**
- `AuthController.java:65` Cookie 仅 `HttpOnly;SameSite=Lax`，**无 Secure**；纯 HTTP(8082) 部署令牌可嗅探。
- `ServerLauncher.cs:950` Spring Boot 默认绑 `0.0.0.0`，叠加默认密钥放大暴露面。
- `InMemoryRevocationStore.java:14` 失效仅单节点内存，多实例不共享。

**【优·正面】**
- `AesCrypto.java:73-105` AES/GCM + 随机 12 字节 IV、认证加密；密钥长度强校验；prod 下 `failFastIfDemoKey()` 拒启，实现正确。
- `AuthService.java:40,85` BCrypt；`Account.java:39` 哈希 `@JsonIgnore` 永不序列化。
- 前端零 `v-html/innerHTML`（Grep 无命中），Vue 自动转义；`Login.vue:90` 重定向仅允许 `/` 且非 `//`，无开放重定向。
- `GlobalExceptionHandler.java:56-61` 异常泛化返回，堆栈只入日志。

**【中·启动器信任边界】**
- `ServerLauncher.cs:488-542` `VerifyJarChecksumOptional` 仅当存在 `<jar>.sha256` 才校验，默认分发无该文件 → 静默放行被篡改 jar（已修复为返回 bool，但默认仍放行属设计取舍）。
- `:725-752` `auto-download-jre` 下载 JRE **无哈希/签名校验**；`auto-jre-url` 可设为 `http://` 明文源 → MITM 替换 JRE。
- `:946-950` 启动参数拼接：`cfgProfile` 未加引号可注入 `--spring.*`；`jarPath` 仅引号包裹，路径含 `"` 可逃逸注入 JVM 参数（`-javaagent:` RCE）。建议对 `cfgProfile` 加引号、路径做字符白名单。

**建议**：生产文档强制要求 `token-secret`/`APP_CRYPTO_KEY` 必填并从环境变量注入；启动器 Cookie 在 https 场景补 Secure；JRE 下载加签名/哈希校验；启动参数做引号包裹与字符白名单。

### 维度② 领域正确性与统计口径（评分 6.0）

**【高·正确性缺陷】家长全校排名使用跨校全局名次**
- `RankingService.java:72` 家长 `schoolFilterForStatistics` 返回 `null`；`:168-173` 在完整 `ranked` 上 `assignRank` 后再按 `bound` 过滤，家长 `sc=false` 看到的名次是**跨校全局名次**而非本校名次，且名次语义错误（越校数据参与计算）。
- 建议：家长路径必须对 `rankRows` 传 `schoolId`（按学生归属校过滤），`assignRank` 在已校域过滤后的集合上执行。

**【中】及格/优秀/分数段用四舍五入后的百分做阈值判定**
- `StatMath.java:48-55,63-67`、`isPass/isExcellent/distribution` 用 `round1` 后的 `percent`（`:44` 先四舍五入）。边界 `[59.95,60)`、`[84.95,85)` 会被误判。阈值应基于原始 `score*100.0/full` 比较，再展示四舍五入值。

**【中】同场同科 teacher+parent 双成绩导致标准分/趋势重复计数**
- `StatisticsService.java:197-203` 与 `TrendService.java:178-180`：唯一约束含 `source`（`Grade.java:9-11`），同 exam+course 可同时存在 teacher 与 parent 成绩，二者均进入 `stdItems/courseItems`，标准分与该场 trend 对该科**双重计数**；`studentMultiSubject` 的 `totalScore` 仅计 teacher，但 `stdScore` 混入 parent，口径不一致。

**【中】进步/退步基线因人而异**
- `TrendService.java:102-114`：每位学生取自己"最后两场"考试比较，不同学生的 `(prev,last)` 考试对可能不同却在同一榜单按 `delta` 排名，属"不同基线横向比较"，名次意义失真。

**【低/中】学期维度查询未按校过滤**
- `ComparisonService.java:65`、`TrendService.java:72` `examRepository.findBySourceAndSemester` 无 `schoolId` 过滤，返回跨校考试 ID；`findBySchoolId`（`GradeRepository.java:113`）用 `grade.school_id` 快照而非学生校，快照漂移时可能错漏。

**【低】家长 full 档位与注释不符 + PII 暴露**
- `RankingService.java:180-186` `sc=false` 时 `full` 实际只返回自己（与"返回范围内全部行"矛盾）；`sc=true` 时 `full` 向家长返回全班姓名/学号/分数（大范围 PII 暴露，设计为"明确授权"但需再评估）。

**建议**：按上述逐项修正口径；`percentAvg` 用四舍五入百分再平均的微小偏差一并修正；`filterGradeRowsByClass` 对 `cid==null` 跳过可能漏统需确认。

### 维度③ 代码异味 / 冗余 / 技术债（评分 6.0）

**【中】迁移双机制并存**
- `SchoolIdMigrationRunner.java:18-25` 与 `db/migration/V2__backfill_school_id.sql` 两套 school_id 回填机制并存，默认关闭但逻辑重复、口径须手动同步。

**【中】schoolId 取数口径三处分散**
- `DataScopeService.currentSchoolId()`(:41) 已封装，但 `DictionaryService.java:52` 自写 `currentSchoolIdOrNull()`、`SettingsService.java:51` 自写私有 `currentSchoolId`，且 `LevelService/ExamService` 直接用 `LoginUserContext.requireLogin().getSchoolId()`，三套写法并存，应统一复用。

**【中】可疑修复/双重赋值**
- `ServerLauncher.cs:532` 在 `VerifyJarChecksumOptional` 内副作用式写 `jarOk=false`，调用方 `CheckJar`(:490) 收到 false 后又赋一遍。`jarOk=false`；方法既返回 bool 又改字段，双重赋值易致混淆。建议方法纯粹返回 bool，由调用方统一置位。

**【低】僵尸占位分支**
- `AuthController.java:125` 调 `AuthService.wechatLoginPlaceholder`(:323) 为永久"未启用"占位（抛固定异常）。建议用 `UnsupportedOperationException` 或移除端点。

**【低】前端占位死代码**
- `frontend/src/api/http.js:20` 请求拦截器 `(config) => config` 空实现（注释"保留以满足契约测试"），可删。

**【中】注释误导 / 异常兜底**
- `AesCrypto.decrypt`(:102) GCM 失败抛 `IllegalStateException`；`AuthService.deriveDefaultPassword`(:227) 经其调用，若某条绑定密文损坏会直接 500，且解密失败被当异常而非"无默认密码"。建议捕获并返回 null 友好降级。
- `GradeService.batchCreate`(:166-176) 唯一/超分冲突静默 `skipped++`，不向用户返回具体跳过原因，可能掩盖录入丢失。建议返回明细。

**【低】魔法数字硬编码**
- `AuthService:37-38`(5/15min)、`ServerLauncher.cs:98`(端口 8082)、`minJavaVersion=21`、HealthMaxTries=90 等多处硬编码，应集中配置。

**【优·正面】** `@Transactional` 自调用排查：逐一对 `StudentService/GradeService/AuthService` 等调用链排查，未发现同类自调用导致事务失效实例。

### 维度④ 文档契约与代码一致性（评分 7.5）

**【中】API 契约失真（wechat 接口）**
- `WebConfig.java:26` 仅排除 login/register/logout；`AuthInterceptor` 对未排除路径强制 token。`API 契约`称 wechat"公开（本期不做）"，实际需登录（401 后再抛未启用）。建议契约改"需 token 的占位接口"或 WebConfig 放行。

**【中】登录请求体多出 phone 字段**
- `LoginRequest.java:8-22` 仅 username/password/role；`API 契约`写 `{username, phone, password, role}` 且称家长=`学生姓名`+`手机号`+`密码`。事实：家长登录把手机号当作 username 传入（`findByLoginName` 按 username/phone 查），无独立 phone 参数。建议契约改为 `{username, password, role}`。

**【中】字段规范 scope_type 取值缺失**
- `字段规范`仅列 CLASS/ALL；但 `Account.java:23-26`、`AuthService.java:262/:202` 支持 SCOPE_SCHOOL 三态。建议规范补 SCHOOL 语义。

**【中】H2 console 默认值注释错误**
- `application-pg.yml:22`、`application-prod.yml:4` 注释"base 配置默认开启"；但 `application.yml:28` 默认 `false`。建议更正两处注释。

**【中】publish.ps1 被多处文档引用却缺失**
- 启动器设计文档、`全面清理与审查报告`、`二轮全新视角`等引用 `publish.ps1`；实际 `publish/` 与 `tools/` 均无该文件（仅 compile_launcher.ps1、README.txt、launcher.ini）。建议删除引用或补回脚本。

**【中】字段规范 H2 ddl-auto 不符**
- `字段规范`称"H2 create-drop"；`application.yml:19` 文件库用 `update`，`application-prod.yml:23` 用 validate。建议规范更正。

**【低】文档间矛盾**：测试基线计数 `字段规范`"34 项" vs `API 契约`"64 项 JUnit"。
**【低】注释误导**：`Account.java:56` 注释"CLASS/ALL"遗漏 SCHOOL，与同文件:23-26 自相矛盾。
**【低】说明过期**：启动器设计文档写 `port-auto-fix=false 默认关`；`launcher.ini:7` 与 `ServerLauncher.cs:120` 默认均为 `true`（整改已统一 true，文档未同步）。

**【正向已核实一致】**：登录锁定 5 次/15 分钟（`AuthService.java:36-38`）、注册老师返回 400、AES 密钥 `APP_CRYPTO_KEY`、grade 冗余 `school_id`+`idx_grade_school`、端口 8080 经启动器 `--server.port=8082` 覆盖均属实。

## 四、结论

全新四路独立审查共暴露 **1 项高危（家长跨校排名）、多项中危（默认密钥暴露面、统计边界与重复计数、启动器参数注入、文档契约失真）** 以及若干低危技术债/文档瑕疵。四个维度诚实评分分别为 6.0 / 6.0 / 6.0 / 7.5。

本次审查与上一轮"整改修复效果复评（四路 ≥9.5 一致认可）"使用不同评分标准：前者评估"已落实修复的有效性"，后者评估"全量独立发现的剩余风险"。两者不冲突——修复项仍然有效，但系统在新维度下仍存在上述待治理项。

建议据此形成下一轮整改任务清单（P0→P1→P2），按"最小改动、独立修复、改前评估连带影响"原则逐批落地。
